## 需求背景

对既有 MMN 开发成果进行一次独立、可恢复、可复核的技术审计，区分线上事实、候选分支回归和单纯分支差异，并在不触碰原工作区与原业务数据的前提下修复关键问题。

## 基线与问题分析

1. 原候选提交为 `8c6285e15d9a1819d9bcc68137ed1d9332dbcf79`。
2. 远端主线为 `61b07bfd982c025a1a0e2be58ff6df19c2bb849b`。
3. 生产部署标记、公开健康接口和容器状态共同证明实际部署提交为 `7cee9d13cdfc956efa1792fdedcc2085a1519769`。
4. 候选与主线从共同祖先分叉；候选缺少生产已发布的认证密钥隔离、可信代理、内部调度签名、原始上传读取边界和中性错误回显。
5. 周度摘要测试使用固定自然周，随日期推进会被新鲜度门禁拒绝。
6. 社媒采集测试虽替换了网络调用，却仍隐式依赖真实环境密钥，导致干净工作树的发布门禁误报失败。

## 技术方案与实现

1. 建立独立工作树、仓库 bundle、未提交差异补丁、三个活动数据库备份和完整数据文件指纹。
2. 将生产已验证提交 `7cee9d1` 合并到审计分支，保留候选中的通用线索看板能力，并解决服务端与历史工单冲突。
3. 增加安全回归测试，覆盖云端认证密钥失败关闭、仅可信代理可提供来源地址、内部调度签名和原始上传边界。
4. 为周度刷新入口增加可选核验日期，只用于确定性测试；生产调用保持原默认行为。
5. 社媒采集测试在每个用例内设置测试占位密钥并在结束后恢复环境，网络搜索仍由测试替身接管。
6. 重构本地发布门禁：在任何测试之前建立隔离环境，拒绝复用已有服务，使用独立端口、临时数据目录、只读源库在线备份和每个 Python 模块独立数据库；完整运行所有 Node/Python 测试，并纳入状态包一致性检查。
7. 对“源库到只读快照、服务启动前后、浏览器验收前后”分别执行逐表逻辑对比，同时核验门禁前后工作树差异与未跟踪文件指纹；测试 HTTP 服务即使初始化失败，也通过类级清理钩子恢复全部测试替身。
8. 将 DOMPurify 与 PostCSS 锁定到已修复版本，不改变业务接口。
9. Eval 默认数据与输出路径遵循 `MMN_DATA_ROOT`/`MMN_OUTPUT_ROOT`，避免测试或隔离运行回写仓库目录。
10. 社媒证据仓库的默认数据库与原始归档路径改为遵循 `MMN_DATA_ROOT`，并增加回归测试；门禁可据此证明全流程不在工作树生成业务文件。
