# beta 1.03 车型全驾驶舱综合决策闭环报告

## 目标与边界

- 在现有决策驾驶舱内部增加统一的车型综合决策层，不新增导航，不重构八类上游看板。
- 固定闭环为 `Evidence → Insight → Decision → Action → Result → Learning → Know-how`。
- 所有事实结论保留证据 ID、时间窗、事实/推断/假设/未知类型和数据指纹；缺失保持缺失，不用模型补齐。
- 报告、结果和人工裁决只追加版本，不覆盖旧记录。正式 Learning 和 Know-how 必须经过门禁与人工裁决。
- 本轮仅本地实施和验证；未部署、未推送 GitHub、未写入生产业务数据，也未涉及 Sales Credo。

## 实现结构

### 决策领域层

`vehicle_decision.py` 负责快照、信号、冲突、报告、Action、Result、Learning Candidate、Know-how Candidate、人工裁决和导出。该层不调用上游分析任务，只消费已存在的确定性结果。

八类表面固定为：高管摘要、集团影响、销量预警、赛道环境、政策环境、传播势能、平台阵地、产品用户之声。任何未接入或当前无数据的表面都会生成 `missing + unknown` 的显式覆盖记录。

### 接入适配层

`server.py` 增加只读适配器，将当前已持久化的集团驾驶舱、销量预警、政策分析、社媒快照、垂媒排名、项目快照和分析任务结果转换为统一 `decision_signal`。适配过程不修改上游表。

### API 与界面

- 快照：创建、列表、详情；服务器端冻结实际八表面输入，忽略客户端自报事实。
- 报告：按快照生成不可变版本、列表、详情、人工发布、Markdown/PPTX 导出。
- 裁决：关键冲突人工裁决并保留理由、用户与时间。
- 闭环：Action 建立/状态转换、Result 追加版本、Learning/Know-how 候选生成与人工复核。
- 界面：`vehicle-decision.js` 和 `vehicle-decision.css` 注入现有决策驾驶舱，保持原有信息架构；包含八表面覆盖矩阵、报告版本、冲突队列、Action 表单、结果表单和闭环状态。

## 持久化契约

本轮新增十张增量表：

1. `vehicle_decision_snapshots`
2. `decision_signals`
3. `decision_reports`
4. `decision_conflicts`
5. `human_adjudications`
6. `action_cycles`
7. `action_results`
8. `learning_candidates`
9. `knowhow_candidates`
10. `decision_evidence_links`

所有核心记录包含 `org_id`，并按组织校验读取和写入。报告版本以快照为粒度递增，Action 引用已发布报告与具体 Decision，Result 按 Action 追加版本。指标中的 JSON `null` 表示未回传，数值 `0` 表示真实零值。

Learning Candidate 至少要求：已观察 Action、执行前基线、真实 Result、反证、其他可能解释、适用与不适用边界。观察窗口未结束时状态固定为 `needs_more_observation`，不能批准。

Know-how Candidate 默认至少需要两个已批准 Learning。单个 Learning 只有在 `ellisWaiver=true` 且保留明确豁免理由时才可生成候选；候选仍需人工批准。

### 真实浏览器业务流

在隔离数据库与 `http://127.0.0.1:8876/` 完成奥迪 E7X 流程：

1. 冻结八表面快照，读取到集团影响、销量预警、赛道环境三类信号，其余五类显式缺失。
2. 生成并发布 v1、v2 两个不可变报告版本。
3. 建立两个 Action，完成状态转换并各记录一个 Result。
4. 第一条未来结束窗口生成 `needs_more_observation`，界面不提供误批准入口。
5. 第二条已结束窗口生成 `pending_review`，完成一次人工批准；刷新后仍显示 2 Action、2 Result、1 已批准 Learning。
6. 真实零值 `volume=0` 与其他未回传指标 `null` 同屏显示且未混淆。
7. PPTX 与 Markdown 导出请求均为 HTTP 200。
8. 1440px 和 390px 下 `scrollWidth == clientWidth`；控制台 0 error、0 warning。
9. 以主库副本运行 `scripts/release_gate_all_surfaces.js`：19 个客户导航入口、八类管理驾驶舱、E7X 上下文联动及跨车型数据清理在桌面/390px 全部通过，`failed=[]`、`runtimeErrors=[]`、`failedResponses=[]`。纯空库首次运行因没有 E7X 预警实体在脚本固定联动步骤超时，改用复制后的临时库通过，源主库未被门禁写入。
