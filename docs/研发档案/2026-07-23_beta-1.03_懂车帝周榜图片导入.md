# 懂车帝周榜图片导入

## 目标

允许竞品格局读取懂车帝自然周正反向排名截图，在人工复核后纳入现有竞品资产与后续决策链路。

## 数据边界

- 只接收懂车帝周榜图片；汽车之家图片明确拒绝。
- 图片识别结果先保存为草稿，不直接进入正式竞品资产。
- 用户必须核对平台、连续七天自然周、本品车型、竞品名称及正反向排名，并明确确认原图平台与本品车型。
- 正向排名必须完整连续，反向排名必须为正整数；校验失败时不写入正式资产。
- 确认写入与草稿状态更新使用同一事务；相同证据和确认内容重复提交保持幂等。
- 识别失败、来源不明或图片证据被替换时返回明确缺口，不以推测值补齐。

## 实现

- 后端新增图片预览和确认接口，复用现有竞品资产持久化入口。
- 前端新增图片选择、原图对照、可编辑复核表、本品确认及错误提示。
- 本地优先使用可用的 OCR 运行时；macOS 使用系统文字识别，Linux 使用中文 Tesseract 的稀疏表格模式，并按同一行内的列间距恢复单元格。
- Linux 未可靠识别图片顶部平台字样时，只有“完整周周期 + 完整三列表头 + 连续 Top 10”同时成立才允许进入人工复核，并显示平台核对警告；用户必须勾选“原图为懂车帝周榜”后才能确认。识别出“汽车之家”时仍直接拒绝。

## 验收

- 真实懂车帝截图识别出 `2026-07-13至2026-07-19` 的10行排名；人工确认智己LS6后写入1个批次、10条关系。
- 相同确认重复提交不新增批次或关系。
- 真实汽车之家截图在预览阶段拒绝，正式资产不变。
- 1440px与390px真实页面完成上传、复核、确认和错误提示；无页面整体横向溢出或控制台错误。
- 图片专项后端与前端合同已纳入仓库发布门禁。

## 生产门禁补充

- 首次生产真实图片验证发现：macOS 系统文字识别通过，但 Linux 默认 Tesseract 将整行表格合并，且未可靠读出顶部“懂车帝”，导致同一张图在生产预览失败。
- 已补充 Linux 稀疏表格识别、按列聚类和强结构人工复核门禁；修复必须通过同一张真实图片的生产上传验证后方可收口。

## 发布状态

生产补丁验证中；正式竞争格局尚未因验收图片发生写入。
