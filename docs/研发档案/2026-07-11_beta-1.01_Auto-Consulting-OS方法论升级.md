# beta 1.01 Auto Consulting OS 方法论升级

## 研发日期

2026-07-11

## 版本号

beta 1.01（方法论与开发治理更新）

## 需求背景

MMN 需要从“汽车营销策略系统”进一步明确为 Auto Consulting OS，同时保持汽车行业方法论优先，避免通用咨询框架和平台指标替代真实购车决策判断。

## 问题分析

现有 MMN Strategy Model 已覆盖本品、竞品、情绪、属性、身份、定位、认知空位和传播动作，机会地图也具备模型交叉复核与证据引用基础。但现有方法论文档尚未统一规定：

- 事实、推断、假设和未知的分类与透明要求。
- 问题树和假设登记的汽车行业落法。
- 来源独立性与多源交叉验证标准。
- 反向压力测试和冲突证据处理。
- 策略取舍、执行动作、验证指标、停止条件和不做事项。

## 技术方案

新增 `docs/mmn-auto-consulting-os.md` 作为统一方法论与输出契约，并由以下入口引用：

- `docs/mmn-strategy-model.md`
- `README.md`
- `AGENTS.md`

方法论优先级为：`develop-auto-marketing-strategy` 负责汽车行业核心判断，`management-consulting` 只补充结构化问题求解，`market-research` 只补充研究与证据治理。

## 功能实现

- 建立汽车购车决策主链和汽车行业问题树。
- 建立事实、推断、假设和未知四类声明规则。
- 建立来源独立性、最低证据组合和冲突处理规则。
- 建立机会地图与策略的反向压力测试。
- 建立机会地图和策略交付的必备字段与质量门禁。
- 在项目级智能体规则中设置为所有 MMN 策略与研究任务的必读方法论。

## 修改模块

- MMN Strategy Model 文档。
- 项目 README 核心定位。
- Auto Consulting OS 方法论单一事实源。

## 版本变更说明

本次变更完成方法论与开发治理层升级，不宣称现有所有接口已经自动生成结构化的四类声明字段。后续运行时改造应在不覆盖当前未提交机会地图实现的前提下，按 TDD 分阶段将该契约接入模型提示词、机会地图数据结构、策略输出、前端展示与质量门禁。

## 后续计划

1. 为四类声明、证据独立性和压力测试建立可验证数据 Schema。
2. 将方法论契约接入机会地图和策略生成提示词。
3. 将缺字段或证据不足的结论自动降级为待补证/待人工确认。
4. 在现有信息架构内增加证据透明展示，不新增或重命名一级/二级模块。
5. 完成测试、构建、真实浏览器验收和独立代码审查后再进入发布流程。
