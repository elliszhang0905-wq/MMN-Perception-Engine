## 需求背景

MMN Perception Engine 已完成基础产品框架、核心模块、模型调度、知识库、数据导入、云端部署基础与本地运行保障。为后续 GitHub 管理、服务器稳定演示和商业化迭代，需要建立清晰的版本命名与发布边界。

## 问题分析

当前系统已经具备可演示的完整产品形态，但部分数据模块仍处于小样本演示阶段，云端环境也尚未进入正式生产级客户开放状态。因此当前版本不宜直接定义为正式生产版，应区分本地研发基线与云端稳定演示基线。

## 技术方案

1. 新增版本定义文件，明确本地版本与服务器演示版本的命名规则。
2. 将本地版本定义为 `MMN Perception Engine v1.0-beta`。
3. 将服务器版本定义为 `MMN Perception Engine v1.0-beta Demo Stable`。
4. 明确服务器版本仅在收到发布指令后更新，避免本地实验功能影响客户演示。
5. 保留 `release.md` 作为后续正式发布记录模板。
