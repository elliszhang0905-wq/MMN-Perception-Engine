# 品牌周度传播战情室交互 Demo

## 研发信息

- 研发日期：2026-07-12
- 版本：交互 Demo 0.1
- 研发团队：MMN研发团队

## 需求背景

为验证“按品牌自动识别本周动作、三平台热门事件、热度依据、事件来源类型及品牌横向对比”的页面信息结构，新增一个不接入正式导航、不影响现有路由的独立交互 Demo。

## 问题分析

当前首要问题是确认品牌市场负责人能否在一屏内完成三个判断：本周发生了什么、为什么值得关注、证据能否下钻。正式数据采集仍需单独完成真实接口验证，因此本页面明确使用模拟数据，不把样例指标表达为真实品牌事实。

## 技术方案与功能实现

- 使用单文件 HTML、CSS、JavaScript，避免增加运行依赖。
- 复用 MMN 既有冷灰、深色、青色、绿色、红色与琥珀色视觉 Token。
- 提供品牌筛选、平台筛选、事件选择和证据面板同步交互。
- 展示周度传播脉冲、核心指标、事件分类、热度评分、代表内容和品牌横向对比。
- 桌面和移动端响应式布局，支持键盘触发事件卡片并遵守减少动态效果偏好。

## 修改模块

- `demo-brand-weekly-radar.html`：新增独立 Demo 页面。
- 本研发档案：记录原型目的、范围与验证结果。

## 测试结果

- Chrome 桌面端 1440px：页面完整渲染，无横向溢出。
- Chrome 移动端 390px：页面完整渲染，无横向溢出。
- 品牌筛选：切换“理想”后仅保留对应事件，证据面板同步更新。
- 平台筛选：切换“小红书”后事件列表正确过滤。
- 空筛选组合：事件列表与证据面板同时进入空状态，不保留旧事件证据。
- 事件下钻：点击和键盘操作均可更新证据链。
- 选中状态：当前事件和品牌筛选均提供视觉与程序化状态。
- 浏览器控制台：无错误。

## 版本变更说明

本次仅新增独立 Demo，不修改 MMN 现有信息架构、左侧导航、一级/二级模块、路由、后端接口或正式数据。

## 后续计划

待页面方向确认后，再决定是否进入正式功能开发。正式版需要先验证抖音、微博和小红书数据源，再补充事件聚类、热度归一化、证据哈希、人工复核和快照恢复能力。
