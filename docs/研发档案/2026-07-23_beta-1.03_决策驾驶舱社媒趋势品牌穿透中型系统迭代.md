# beta 1.03｜决策驾驶舱、社媒趋势与品牌穿透中型系统迭代

## 研发日期

2026-07-23

## 发布版本

`beta-1.03-20260723-cockpit-social-brand-1`

## 目标与价值

对决策驾驶舱、社媒趋势中心和品牌穿透中心做一次跨模块完整巡检，修复会阻断真实使用、造成状态失真或让旧请求覆盖新结果的问题，并把品牌传播证据进一步收敛为逐品牌结论和“本品 × 每个竞品”结论。所有结论继续遵守证据边界，不把传播相关性外推为市场渗透、购买意愿或销售因果。

## 范围与非目标

本次覆盖三大中心全部客户入口、管理层入口、桌面与移动布局、历史快照恢复、筛选与下钻、失败与恢复、持久化和发布回归。公开社媒证据 V2 代码随包交付，但生产开关保持关闭，独立 Worker 不启动。

本次不重采、覆盖或删除历史证据，不改写销量与产品评价数据，不改变社媒热度和跨平台统计口径，不为证据不足项目补造结论，也不修改其他产品或公开域名路由。

## 发现并修复的问题

- 社媒趋势中心在 V2 关闭时没有继续读取既有最新快照，首次进入页面长期停留在空白状态。
- 恢复历史快照后，页面仍显示默认 30 天、3 个竞品，与快照实际 7 天、1 个竞品不一致。
- 没有快照时缺少可理解、可继续操作的空态。
- 历史恢复请求可能晚于用户新发起的分析或导入返回，并覆盖更新结果。
- 前端版本号和品牌内嵌页面缓存令牌滞后，存在发布后继续使用旧资源的风险。
- 品牌穿透中心只有事件和证据列表，缺少逐品牌及本品逐竞品的统一交叉验证结论。

## 工程契约

- 社媒趋势优先读取当前能力路径；V2 关闭时自动回落到既有权威快照接口，不以空白代替已有数据。
- 恢复快照时同步恢复时间窗、竞品与平台；没有快照时显示明确空态和启动入口。
- 用户开始新分析或导入时立即取消旧恢复请求的写入资格，晚到响应不得覆盖新状态。
- 品牌三路复核共享同一冻结证据指纹，首轮相互不可见；按品牌、按竞品对照分别做确定性融合。
- 任一路失败、越界引用、结构不完整或三路方向不一致时，相关项目保持降级或人工复核，不用两路意见冒充共同结论。
- 客户侧只展示中性的 MMN 结论、状态和证据，不暴露底层供应商、原始异常或技术指纹。

## 验收矩阵

- 正常：三中心入口、筛选、下钻、数据切换、历史恢复、品牌 6 张结论卡与 5 张逐竞品卡均可用。
- 边界：194 条唯一证据不因历史跨品牌分组重复扩张；旧快照的 7 天、1 个竞品和三平台范围准确恢复。
- 失败：证据不足、结构失败、通道超时和无历史快照均显示诚实状态，不发布推测结论。
- 恢复：刷新后恢复相同快照；用户启动新分析或导入后，旧恢复响应不能回写覆盖。
- 持久化：品牌结论与冻结指纹随快照保存；既有历史数据不被覆盖或删除。
- 真实流程：品牌卡可定位对应竞品事件和证据；社媒趋势真实历史快照恢复 49 条内容；驾驶舱全导航与数据切换完成回归。
- 桌面与移动：1440px 和 390px 均无页面横向溢出、控制台运行错误或失败请求。
- 回归：全量 Python 586 项通过；全部 Node 合同通过；发布门禁 161 项及全表面浏览器门禁通过，结果均为 `failed=[]`、`runtimeErrors=[]`、`failedResponses=[]`。

## 数据保护

真实写路径前分别备份商业数据库与社媒证据库并记录 SHA-256。提交只包含本次代码、测试、状态与研发档案；仓库内既有未跟踪备份、输出、用户文档和并行工作均不纳入提交。发布前后需要继续执行数据库逐表逻辑一致性、`quick_check`、服务健康、提交标记和镜像文件校验。

## 发布与残余风险

GitHub `main`、发布分支、本地 8765、ECS 六服务和交接档案均已完成发布。生产继续保持公开社媒证据 V2 与独立 Worker 关闭。外部复核服务的时延与格式波动仍可能让个别品牌项目进入复核未完成或待人工复核，这是预期的失败关闭状态，不得被自动补齐。公网 `mmnsh.com` 仍受既有 ICP/TLS 边界阻断，本轮未改动路由。
