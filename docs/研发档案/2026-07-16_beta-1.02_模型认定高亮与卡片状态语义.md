# beta 1.02 模型认定高亮与卡片状态语义

## 目标

让管理层在阅读集团判断时更快找到核心结论，并让“集团判断、传播动作、复盘信号”每张卡片都有独立的当下状态定义。

## 高亮规则

- 车型判断结构增加 `highlights` 字段，每条包含原文字段、逐字引文、优先级和理由。
- 服务端只接受原文中真实存在的短引文，自动过滤改写、重叠、过长和过量高亮。
- 前端使用文本切片方式渲染，不执行返回内容中的标记代码。
- 主高亮用于商业结果或核心判断；次高亮用于关键转折或行动支点。
- 本地规则兜底未完成认定时不自动高亮。

## 状态语义

- 绿色：“机会放大”，表示优势势能正在形成，应继续加码有效表达和正向信号。
- 黄色：“重点补强”，表示关键认知或传播任务需要加速，相关指标需加密追踪。
- 红色：“紧急行动”，表示已形成重大认知风险，需立即启动传播修复与高频复盘。
- 三张卡片分别显示当下判断、行动紧迫度和监测要求，不再共用整组底部单一标签。

## 修改模块

- `server.py`：高亮输出约束、服务端校验和持久化。
- `app.js` 与 `style.css`：车型判断工作台安全高亮。
- `group-dashboard.js` 与 `group-dashboard.css`：集团影响卡片重点高亮和三级状态标签。
- `tests/` 与 `scripts/release_gate.sh`：增加高亮安全和卡片状态回归检查。

## 验收标准

- 每个品牌的三张集团影响卡片均显示独立状态。
- 高亮不改变原文内容，不产生任意标记注入。
- 车型判断未完成模型认定时不显示自动高亮。
- 旧数据没有高亮字段时仍能正常显示完整正文。
