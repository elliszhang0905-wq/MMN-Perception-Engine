# beta 1.02 本地服务静默退出与自动恢复修复

## 问题现象

- `127.0.0.1:8765` 无监听进程，本地页面无法访问。
- `logs/local_mmn.pid` 保留的是已退出的旧进程号。
- 再次执行 `scripts/ensure_local_mmn.sh` 时没有启动服务，也没有输出明确错误。

## 根因

`scripts/ensure_local_mmn.sh` 启用了 `set -euo pipefail`。当端口没有监听进程时，`server_pid()` 中的 `lsof | head` 管道返回非零状态，使恢复脚本在启动服务前静默退出。同时，原启动方式只能拉起一次进程，服务后续退出时没有自动恢复机制。

## 修复内容

- 为无监听进程的正常分支补充安全返回，避免 `set -e` 中断恢复流程。
- 为停止旧服务和停止卡死服务的函数补充明确的成功返回。
- 新增 `scripts/run_local_mmn_watchdog.sh`，记录守护进程和子服务进程号；子服务退出后等待 2 秒自动重启。
- 使用 macOS 自带的脱离会话承载守护脚本，避免启动命令结束后守护进程被一起回收。
- 新增脚本结构测试，并纳入 `scripts/release_gate.sh`。

## 实际验收

- 恢复脚本成功启动本地服务，`/api/health` 返回 `beta 1.02` 和 `beta-1.02-20260714-social-data-1`。
- 手工终止子服务进程 `24780`后，守护进程 `24777` 保持不变，2 秒后拉起新子服务进程 `24809`。
- 重启后再次请求 `/api/health` 成功，证明自动恢复链路有效。

## 环境说明

曾尝试使用 LaunchAgent 承载服务，但 macOS 对后台进程访问 `Documents` 目录的权限限制会阻止 Python 读取 `server.py`。该方案已撤回，当前本地服务不依赖 LaunchAgent。
