# beta 1.03 静态资源边界加固

## 状态

- 当前状态：本地实现与隔离验收完成，正式发布执行中
- 发布状态：生产源码、配置、数据库与逐表逻辑指纹已备份，待提交、同步和部署
- 数据范围：不修改业务表、业务记录或看板计算

## 目标

把Web服务的文件读取边界收缩到客户页面实际使用的前端资源，其他项目文件默认不可通过HTTP访问；同时在反向代理增加独立的敏感路径保护，避免单层配置失误重新扩大文件访问范围。

## 实现

- 应用层使用显式前端资源白名单，首页、页面脚本、样式、图标和同源内嵌页面继续可用。
- GET与HEAD共用同一文件访问门禁。
- 编码路径、双重编码和目录穿越片段不能绕过白名单。
- Nginx拒绝数据、备份、日志、内部文档、源代码和部署配置路径。
- 应用与Nginx补充`nosniff`、同源框架和来源策略响应头。
- 发布门禁加入真实HTTP边界测试，同时验证合法页面资源和API仍可访问。

## 验收

- 修复前，新增测试能够复现未授权文件访问。
- 修复后，合法首页、脚本、样式、图标和API返回200。
- 非公开文件、目录及编码绕过请求返回404。
- Nginx配置在与生产一致的镜像和网络中通过语法检查。
- 临时Nginx实例通过合法资源与敏感路径双向验证。
- Python 615项测试通过，JavaScript 31个测试文件通过。
- 隔离数据副本完成1440px与390px真实页面验收，控制台错误与警告均为0。
- 测试数据库发布前后逐表、逐主键、逐字段对比，变化表为0。

## 发布边界

- 本次不迁移数据库，不修改会话机制，不改业务接口输出合同。
- 正式发布前仍需完成生产代码和数据备份、版本记录、正式数据零漂移基线及回滚点确认。
- 正式发布后必须通过公网入口复验文件边界，并观察访问日志中是否仍有非公开路径返回200。
