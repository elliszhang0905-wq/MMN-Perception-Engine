# MMN Perception Engine 研发记录

## 研发日期

2026-06-27

## 版本号

v1.3.1

## 需求背景

创始人蒸馏模块在手动触发“MMN蒸馏”后，会短暂出现新增高管或新增内容，但页面重新打开后又回到基础归档状态，造成展示状态与数据归档状态不一致。同时，公开网页巡检存在将媒体首页、导航页等低质量内容误识别为高管公开表达的风险。

## 问题分析

1. 高管IP话术生成结果仅保存在前端临时状态和策略知识库中，未同步写入创始人蒸馏归档表。
2. 周度巡检公开源配置包含媒体首页，首页内容容易混入导航、车型、新闻列表等非发言素材。
3. 数据归档层缺少对首页 URL 的强拦截规则，导致仅依靠文本噪音判断仍有误入库风险。
4. 基础样例库缺少蔚来李斌样例，初始人物数量不足以支撑页面稳定展示。

## 技术方案

1. 关闭媒体首页类公开源的默认巡检入口，明确首页不进入蒸馏归档。
2. 增加创始人蒸馏素材持久化门槛，对首页、导航页、车型筛选页等非具体内容页进行底层拦截。
3. 将高管IP话术生成结果同步沉淀到创始人蒸馏归档表，确保生成、展示、刷新后的数据一致。
4. 补充蔚来李斌基础样例，使初始化人物归档保持稳定。
5. 优化前端提示：当周度巡检未发现合规素材时，明确提示需要具体文章、采访、发布会、直播文字稿或社媒导出内容。

## 功能实现

1. 新增 `founder_source_url_is_specific` 与 `founder_item_is_persistable` 校验逻辑。
2. 调整 `FOUNDER_PUBLIC_SOURCES`，媒体首页默认不启用。
3. 调整 `save_founder_items` 与 `founder_archive_rows`，从写入和读取两端拦截低质量来源。
4. 调整 `/api/ai/founder-talk`，生成高管IP话术后自动写入归档库，并返回归档记录。
5. 调整前端 `generateFounderTalk`，生成完成后重新加载归档库。
6. 调整前端 `runFounderWeeklyCrawl`，对 0 条结果给出清晰业务提示。

## 测试结果

1. 后端语法检查通过。
2. 清理媒体首页误入库记录后，污染记录数为 0。
3. 基础样例导入后，创始人蒸馏归档稳定为 4 位人物：李想、何小鹏、雷军、李斌。
4. 手动触发周度巡检后，未发现合规素材时返回 0 条，且不写入媒体首页噪音。
5. 高管IP话术生成接口已验证可写入归档库；测试记录验证后已清理，避免污染演示数据。

## 版本变更说明

本版本修复创始人蒸馏模块“临时展示与持久归档不一致”的问题，并建立首页级低质量来源拦截规则。后续创始人蒸馏页面将以归档库为唯一稳定数据来源，避免刷新后人物或内容丢失。

## 后续计划

2. 增加具体文章链接、采访文字稿、发布会速记稿的手动导入入口。
3. 建立高管人物库与品牌库维护机制，区分基础样例、公开素材、生成话术资产三类数据。
