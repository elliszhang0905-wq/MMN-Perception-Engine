# beta 1.03 竞品格局服务器权威存储修复

## 问题

竞品格局导入较大正反向关系表后，页面提示浏览器存储容量不足，并把已经写入服务器的数据误报为“垂媒数据导入失败”。刷新页面还可能回退到旧缓存或默认筛选。

## 根因

- 完整关系数据已经写入服务器 `vertical_rank_assets`，前端随后又把同一批 `items`、`sources` 和资产摘要写入 `localStorage`，形成重复主存储。
- 项目快照继续携带完整 `verticalState`，进一步重复保存关系明细。
- 服务器恢复接口单次最多返回 5,000 条；本地真实资产已有 5,682 条，存在静默截断。
- 页面在服务器数据返回前会用空列表校正筛选项，导致已保存的车型选择被默认值覆盖。

## 修复

- 服务器数据库成为完整垂媒关系的唯一权威源；浏览器只保存平台、来源、本品、竞品和周期选择。
- 旧版大缓存先保留在当前会话；只有服务器确认恢复成功后才迁移为轻量状态，服务器无数据或读取失败时不删除旧数据。
- 项目快照只保存轻量垂媒上下文，不再复制关系明细。
- `/api/vertical-assets` 增加 `offset`、`total`、`hasMore` 和 `nextOffset`，前端按页读取完整资产。
- 导入成功与浏览器偏好保存失败分开处理；偏好失败不再把服务器导入成功改写成导入失败。
- 服务器数据尚未返回时不校正筛选项，避免刷新覆盖用户选择。

## 验证

- Node 语法检查、垂媒状态持久化回归、前端生命周期回归和租户隔离/分页回归通过。
- 本地 8765 从服务器完整恢复 5,682 条关系，页面提示数量与数据库一致，浏览器控制台无错误。
- 隔离数据库中构造约 405 万字节旧缓存后执行真实 Excel 导入：服务器保存 2/2 条关系，页面显示导入成功，浏览器状态缩减为 153 字节。
- 刷新后本品、竞品和周期选择保持不变，关系由服务器重新恢复。

## 数据与发布边界

- 真实验收使用隔离数据库，未改写本地正式 `commercial_demo.db`。
- 已随 `beta-1.03-20260723-vertical-social-reliability-2` 提交、推送并部署；生产 82 项桌面/移动门禁通过，原有 76 张表逐表逻辑一致，验收副作用已按主键恢复。
