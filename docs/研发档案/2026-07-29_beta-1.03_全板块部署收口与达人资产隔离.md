# beta 1.03 全板块部署收口与达人资产隔离

## 目标

本轮不把“代码存在”包装成“生产已启用”，而是对 MMN 各板块分别给出安全上线、受控关闭或明确阻塞的真实状态，并修复 TikHub 达人直接采集链路中可导致跨企业读写和重复付费调用的边界。

## 产品结论

- 公开社媒证据 V2、NSR 公开讨论验证、封面提示词和独立 Worker 在缺少真实影子导入、成本与质量验收前继续关闭。
- 政策智能保持 MVP，内容策略保留初稿、复核和降级标记，BF 保持 P0，Eval 只作为离线发布门禁。
- 正式 Know-how 仍需行动结果、重复验证与人工批准；行动预算继续隐藏。
- 旧抖音单视频创作分支和旧 TikHub 达人提交均拒绝原样合并，避免回退主线或绕过证据、费用和隔离门禁。

## 本轮工程合同

- TikHub 作品资产以企业空间、平台和平台作品 ID 共同唯一，两个企业采集同一公开作品时互不覆盖。
- 任务详情、暂停、重试、达人详情、观点判断、作品详情和方法资产均使用登录会话中的企业空间；猜测其他企业 ID 时失败关闭。
- 旧 SQLite 作品按达人所属企业原位迁移；无法证明归属的旧方法资产进入隔离作用域，不向客户空间透出。
- 同一企业、主页、时间范围、样本数和确认达人名的进行中任务返回原任务，不重复排队。
- 单个适配器最多执行 30 次外部请求尝试，网络重试同样计数；达到上限后停止并保留降级原因。
- 播放量缺失继续保持 `null`，不得补成 `0`。

## 验收

- 专项回归覆盖双企业同作品、跨企业任务与达人动作、方法资产隔离、旧表迁移、活动任务复用和请求上限。
- 扩大回归覆盖达人脚本、租户隔离和达人孵化工作台。
- 完整发布门禁必须使用冻结的真实基准数据库副本和隔离数据目录；不得读取或修改正式本地库。
- 发布前后分别比较主业务 SQLite 和达人 SQLite 的表、主键与字段；浏览器验收写入必须按明确主键恢复。
- 本地与生产均需完成管理员 1440px 和 390px 真实流程，健康接口只作为存活证据。

## 未包含

- 不启用公开社媒证据 V2、NSR、封面提示词或独立 Worker。
- 不部署旧抖音创作实现。
- 不把 TikHub 直接采集结果自动发布为内容能力资产或正式 Know-how。
- 不修改 Sales Credo、DNS、TLS、账号或密钥。
