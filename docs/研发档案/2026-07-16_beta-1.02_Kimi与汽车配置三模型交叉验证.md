# beta 1.02 Kimi 与汽车配置三模型交叉验证

## 目标

在现有千问与 DeepSeek 模型调度之外接入 Kimi，并把车型参数、续航、电池、动力、座椅、智驾、底盘等汽车配置问题升级为三个旗舰模型交叉验证。

## 实现

- 新增独立的 `KIMI_API_KEY`、`KIMI_BASE_URL`、`KIMI_MODEL`、`KIMI_DEEP_MODEL` 环境配置；密钥只保存在未跟踪的 `.env`。
- Kimi 使用阿里云百炼兼容协议入口，旗舰模型为 `kimi-k2.5`，深度复核开启思考模式。
- 新增 `vehicle_configuration_fact` 任务类型，优先级高于一般策略路由，确保“竞品配置对比”等混合表述仍进入配置事实门禁。
- 配置事实仍先读取结构化数据、RAG 或官方来源；模型不得用自身记忆补全配置。
- 千问、DeepSeek、Kimi 必须全部完成、均返回 `supported`、置信度不低于 0.6，并共同引用同一个有效证据 ID，才可标记“三模型一致”。
- 任一模型失败、引用缺失、引用越界、结论不支持、置信度不足或没有共同证据时，统一标记“需人工复核”。
- 用户侧只显示 MMN 三模型验证状态，不直接暴露底层模型原始输出；完整复核记录保留在内部路由审计数据中。

## 验证

- Kimi API 真实调用成功，返回模型为 `kimi-k2.5`。
- 使用一条模拟官方配置证据完成真实三模型调用，千问、DeepSeek、Kimi 均成功，公共证据为 `ref-1`，状态为 `aligned`。
- 新增 4 项单元测试，覆盖任务识别、Kimi 独立配置、三模型共同证据门禁和 Kimi 旗舰路由。
