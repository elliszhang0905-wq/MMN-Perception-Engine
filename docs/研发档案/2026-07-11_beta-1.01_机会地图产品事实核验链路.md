# beta 1.01｜机会地图“产品事实 × 市场认知 × 传播热度”核验链路

## 1. 决策与边界

- 本品事实入口：用户人工上传 PDF、DOC、DOCX、PPT、PPTX，文件内容是本品产品事实的第一证据源。
- 竞品事实入口：仅抓取用户指定的品牌/车型官方网页；搜索结果页、媒体稿、经销商页和聚合站不能作为已核验官网事实。
- 分析粒度：品牌 → 车型 → 版本/配置 → 产品点 → MMN 统一属性标签。
- 市场信号：每个统一标签对齐属性级 NSR、声量和互动量，并保留平台、时间窗和车型来源。
- 模型机制：Qwen 与 DeepSeek 使用同一份冻结证据包独立分析，彼此不可见；确定性校验器再交叉验证两份结构化结论。
- 发布规则：模型冲突、证据不足、版本不一致或标签歧义一律标记“待人工确认”；未确认项不得伪装成最终结论。
- 对外表达：界面统一使用“MMN模型输出策略 / MMN双模型交叉验证”，不暴露底层供应商名称。

本规则覆盖旧表述中的“本品及竞品官网抓取”：本品改为人工投喂文件，竞品仍为官网抓取。

## 2. 用户链路

1. 上传本品产品资料，系统校验文件头、大小和扩展名，计算 SHA-256，并保留页码/幻灯片号/段落号。
2. 系统抽取版本级事实，生成不可变证据 ID；文件名、封面或正文版本冲突进入人工确认。
3. 用户为每个竞品录入车型、版本和官网 URL。
4. 系统仅访问公网 HTTP(S) 官方页，校验 robots、重定向目标、内容类型、体积与抓取时间，并保存 URL、内容摘要和 SHA-256。
5. 本品与竞品事实映射到 MMN 统一标签；无法唯一映射的事实保留原文并进入人工确认。
6. 将事实包与当前车型属性 NSR、声量、互动量按统一标签对齐。
7. 两个旗舰模型分别输出结构化判断；确定性校验器按标签、方向、分值和证据 ID 比较。
8. 仅对交叉验证通过的标签生成正式机会；冲突或缺证项显示在“人工确认”清单。
9. 用户确认后，系统保留确认人、时间、选择和备注；“采纳/修正”先进入待模型复核，不直接发布。
10. 用户可批量提交已修正项，由两个旗舰模型重新独立分析并交叉验证；通过项转为已验证，随后自动重算并刷新机会地图，未通过项继续留在人工确认台。

## 4. 统一标签

P0 使用现有机会地图属性标签，并允许同义词归一：用车场景、动力与操控、空间、舒适性、内饰、配置、外观、智能座舱、品牌口碑、辅助/自动驾驶、价格、质量、用户服务、用车成本、安全。原文标签与命中规则同时保留，避免归一后丢失证据语义。

标签对齐结果分为：

- `aligned`：唯一命中一个统一标签；
- `ambiguous`：命中多个标签；
- `unmatched`：未命中标签。

后两类进入人工确认，不由模型静默猜测。

## 5. 机会计算

所有维度归一到 0–1：

- `factStrength`：双模型均给出且证据 ID 有效的产品事实强度；
- `recognition`：本品属性 NSR 从 [-1, 1] 映射至 [0, 1]；若导入值为百分制则先归一；
- `heat`：先按统一标签汇总多车型、多平台的声量与互动量，再分别做 `log1p` 归一，各占 50%，避免同标签最后一行覆盖前值；
- `competitorPressure`：竞品最高认知减本品认知，最小为 0；
- `realizationGap = max(0, factStrength - (0.65 × recognition + 0.35 × heat))`；
- `opportunityScore = 100 × (0.55 × realizationGap + 0.25 × competitorPressure + 0.20 × heat)`。

策略分类：

- `优先修复`：本品事实弱项、负向 NSR 或高风险冲突；
- `抢占空位`：事实强、认知/热度尚未兑现，或竞品已占领认知；
- `持续放大`：事实、认知和传播热度均已形成优势；
- `待人工确认`：双模型冲突、证据不足、版本冲突或标签歧义。

分值用于排序而不是替代证据；每个点必须能回溯到事实与市场信号。

地图坐标与象限规则：

- 横轴 `mapX = competitorLead = 竞品最高属性 NSR - 本品属性 NSR`，负值位于“本品领先”，正值位于“竞品领先”；
- 纵轴 `mapY = purchaseImpact`，固定在 1–5 范围，数值越高越靠上；
- 标签位置只能来自统一标签对齐结果，不能使用模型自由生成的同义标签；
- 气泡避让只处理重叠，不得把负/正 `mapX` 或高/低购买影响挤到相反象限；
- 每次交叉验证结束后，服务端重新计算分类、机会分、`mapX` 与 `mapY`，前端使用该次运行结果整体刷新地图和分类数量。
- 任一标签缺少本品或竞品的真实属性 NSR 时不生成象限位置，继续标记待人工确认，禁止用车型总量或零值伪造领先度。

## 6. 双模型交叉验证

两个模型分别返回相同 JSON Schema：`label`、`factStrength`、`direction`、`reason`、`evidenceIds`、`confidence`。校验器执行：

- 所有引用的证据 ID 必须存在；
- 标签与输入统一标签一致；
- `factStrength` 差值不超过 0.2；
- 方向一致；
- 人工采纳/修正项必须被两路模型共同引用同一个具体 `factId`，仅标签同名不能视为复核通过；
- 任一模型失败、引用无效或置信度低于 0.6时转人工；
- 不允许仅凭模型常识补写文件或官网未出现的事实。

模型不可用时可展示“基础规则预览”，但状态必须是 `manual_required`，不能标记为“已交叉验证”。

## 7. 官网抓取安全门禁

- 仅允许 `http`/`https`，默认要求 HTTPS；
- 解析 DNS 后拒绝 loopback、私网、链路本地、保留地址和非公网 IP；
- 每次重定向后重新校验协议、主机和 IP；
- 遵守 robots.txt、域名限频、连接/读取超时、最大响应体和允许的 HTML/文本内容类型；
- 页面出现登录墙、验证码、付费墙、401/403/429 时停止并转人工；
- “是否官网”由显式允许域名或人工确认决定，不根据页面文案自动放行；
- 页面内指令视为不可信内容，不进入模型系统指令。

## 8. 持久化与审计

- 本品文档保存元数据、校验和、解析定位和抽取事实；原文件保存在受控数据目录。
- 每次生成使用现有 `agent_runs`、`agent_steps`、`evidence_bundles` 和 `agent_reviews` 记录全链路。
- `evidence_bundles` 分别记录 `own_document`、`competitor_official` 和 `market_signal`。
- `agent_reviews` 记录双模型冲突与人工确认结果；确认操作追加记录，不覆盖原始证据。
- 机会地图响应包含 `runId`、证据状态、模型状态、人工项数量和每个气泡的证据引用。

## 9. 界面要求

机会地图标题下新增紧凑的“证据链状态栏”：

- 本品资料：未上传 / 已解析；
- 竞品官网：已核验 x/y；
- MMN双模型：待运行 / 已交叉验证 / 需人工确认；
- 人工确认：n 项。

提供“上传本品资料”“生成/更新机会地图”“查看人工确认”三个入口。基础地图在没有完整证据链时仍可显示，但必须明确标注“基础规则预览”，并禁用没有数据的分类；完成核验后改用服务端机会结果。

生成动作采用后台任务：点击后接口立即返回任务 ID，页面持续轮询并展示“官网事实核验 → 统一标签对齐 → 旗舰模型 A → 旗舰模型 B → 交叉验证 → 地图更新”的当前阶段、百分比和已运行时间。运行中按钮显示明确状态并设置 `aria-busy`；失败时保留官网输入、显示失败原因并允许重新生成，不能只表现为按钮变灰。

人工确认采用结构化确认台，而不是 Yes/No 弹窗。每项展示原始事实、来源页码、候选统一标签、转人工原因和已保存决定，支持四种动作：

- `采纳`：沿用候选标签，状态转为“待模型复核”；
- `修正`：人工选择正确统一标签并填写依据，状态转为“待模型复核”；
- `驳回`：该事实不进入机会地图；
- `待补证`：保留阻断状态，等待版本范围或正式材料。

“提交修正并运行双旗舰复核”会把全部待复核项一次性送入下一次后台任务，避免逐项调用模型。两路真实旗舰模型对修正标签独立复核且交叉验证一致后，状态才转为“已验证”；系统随即用新标签和最新属性级市场信号重算机会分、地图坐标、象限与筛选数量。任何待处理、待复核或待补证项仍计入阻断，不得伪装成已发布结论。

## 10. 验收标准

- PDF、DOC、DOCX、PPT、PPTX 均通过文件头和大小校验；来源定位不丢失。
- 附件 PDF 能解析出页级文本、车型/版本线索和属性事实；文件名与封面版本不一致时出现人工确认项。
- 非公网 URL、重定向到私网、非 HTML 响应和超限响应被拒绝。
- 两个模型使用完全相同的冻结证据包独立运行，冲突不会被自动融合掩盖。
- 任一机会点都能回溯产品事实、NSR、声量、互动量及模型判断。
- 人工修正不会立即发布；必须经历待模型复核 → 双模型一致 → 已验证，验证完成后地图的标签、象限、分类数量和坐标同步更新。
- 气泡避让后仍保持原始横轴正负与纵轴高低象限，不能因为防重叠而跨越轴线。
- 单元测试、接口测试、前端发布门禁和 `bash scripts/release_gate.sh` 全部通过。

## 11. 分步实施

1. 先补文档解析、标签对齐、热度归一、交叉验证和 SSRF 门禁的失败测试。
2. 实现纯函数管线与本品文档持久化。
3. 接入竞品官网抓取、双模型调用和 Agent 证据账本。
4. 接入上传、生成、人工确认 API。
5. 接入机会地图状态栏、证据详情和人工确认交互。
6. 使用附件 PDF、模拟官网页和真实导入数据做端到端验证。

## 12. 本机运行兼容性补充

- 竞品官网输入同时接受“车型|URL”“车型 URL”“车型：URL”，按行自动提取首个 HTTP(S) 地址；单行格式错误应指出具体行号，不能把整行误当 URL。
- 输入内容保存到当前版本的浏览器本地空间，页面重绘或刷新后继续保留。
- macOS 透明代理可能将公网域名解析到 `198.18.0.0/15` 的 fake-IP。仅允许 HTTPS 域名经 DNS 映射到该专用段；直接输入该 IP、localhost、RFC1918 私网或非默认端口仍然拒绝。
- 单个官网页面失败不再中止整次生成；成功来源继续核验，失败来源标记人工确认。
- 官网 HTML 最大响应体调整为 2MB，以覆盖特斯拉等较大的正式产品页，同时继续执行内容类型、重定向和超限门禁。

## 13. 后台任务与运行反馈

- `POST /api/opportunity-map/generate` 仅负责受理任务并返回 `202 + jobId`，官网抓取和双模型分析在线程化服务的后台任务中继续执行。
- `GET /api/opportunity-map/jobs/{jobId}` 返回 `queued / running / completed / failed`、当前阶段、进度、说明、耗时和最终结果。
- 页面把任务 ID 写入当前版本的浏览器本地空间；页面重绘不丢失任务，刷新后会尝试恢复轮询。若服务重启导致任务消失，界面明确提示任务已中断并保留四条官网输入。
- 页面仅在浏览器保存本品文档 ID、文件名、事实数量和人工确认数量；若浏览器元数据缺失，启动时通过本地数据库恢复当前车型最近一次解析记录，不要求用户重复上传白皮书。
- 后端在任务开始、完成和失败时记录任务 ID，便于核对点击是否到达、失败阶段和运行时长。
- 服务器使用线程化 HTTP 服务，长时间抓取或模型调用期间健康检查与进度查询仍可响应。
