# MMN Perception Engine 研发记录

## 研发日期
2026-06-28

## 版本号
v1.0-beta

## 需求背景
国内版需要从固定模型职责升级为任务路由型双模型架构。系统应根据任务类型自动组织主分析、复核、事实溯源和人工确认流程，避免把底层模型供应商直接暴露为产品能力。

## 问题分析
原有策略接口更多依赖单一路由规则，难以区分策略推理、中文交付、事实解释、数据归纳等不同任务。事实类问题如果直接交给模型判断，容易出现口径不清或事实来源不可追溯的问题。双模型结论不一致时，也需要形成可追溯记录和人工确认回流机制。

## 技术方案
1. 建立 MMN 任务路由层，根据用户问题自动识别任务类型。
2. 策略推理、竞品拆解、逻辑压力测试和反方观点生成优先进入深度推理链路，再进行中文业务语境复核。
3. 中文交付、短视频脚本、PPT 文案、客户报告和长文档归纳优先进入中文交付链路，再进行逻辑漏洞检查。
4. 参数、销量、价格、配置、上市时间等事实类任务优先查询 MMN 结构化数据、RAG 资料和可追溯来源，模型只负责解释。
5. 双模型结论冲突时标记“需人工复核”，保留原始输出、引用来源、置信度和人工最终选择。
6. 人工确认结果写入学习记录，并生成可回流的策略知识条目。

## 功能实现
- 新增任务类型识别：策略推理、中文交付、事实解释、数据归纳。
- 新增统一任务路由函数，输出主分析、复核结论、来源追踪、置信度和冲突状态。
- 新增路由决策记录表，保存双模型原始输出、引用来源和人工确认结果。
- 策略接口和智能体运行接口统一接入任务路由层。
- 前端策略结果增加“需人工复核”提示和人工采纳按钮。
- 空间与权限中的模型路由说明更新为任务路由型表达。

## 修改模块
- 后端模型路由与策略接口
- 智能体运行记录
- 策略结果前端展示
- 人工复核回流接口
- 空间与权限模型路由说明
