# 本地开发 GitHub 版本管理与云端发布流程建设

## 研发日期

2026-06-27

## 版本号

v1.2.2

## 需求背景

MMN Perception Engine 已具备本地运行、GitHub 版本管理和阿里云 ECS 部署能力。为了确保后续功能迭代可以安全、稳定、可回滚地同步到云端演示环境，需要建立一套标准发布流程，明确本地、GitHub 与服务器之间的职责边界。

## 问题分析

如果直接在服务器上手工修改代码，会带来以下风险：

1. 本地版本与服务器版本不一致，问题难以追溯。
2. 服务器 `.env`、API Key 和运行配置可能被误覆盖。
3. 发布失败后缺少明确回滚入口。
4. 每次功能迭代缺少发布记录，难以形成稳定版本基线。
5. 云端演示环境可能运行未确认代码，影响演示稳定性。

因此需要将服务器定位为运行环境，本地作为开发与测试环境，GitHub 作为唯一代码版本来源。

## 技术方案

1. 本地完成代码开发、功能验证和发布门禁检查。
2. 本地确认后提交到 GitHub `main` 分支。
3. ECS 执行 `deploy.sh`，从 GitHub 拉取最新代码。
4. 部署过程中保留服务器 `.env`，避免覆盖 API Key、端口、数据库连接等运行配置。
5. 部署前自动备份当前云端数据。
6. 部署时执行 `docker compose down --remove-orphans`、`build`、`up -d`。
7. 新增 `rollback.sh`，支持按 Git 版本回滚并重建容器。
8. 新增发布记录模板，统一记录版本、变更、测试、云端结果和回滚方案。

## 功能实现
