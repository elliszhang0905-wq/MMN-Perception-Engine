# Positioning 策略模块与 GitHub 云端发布链路整理

## 研发日期

2026-06-27

## 版本号

v1.2.4

## 需求背景

云端核心模型能力检查后，发现 MMN Strategy Model 已具备本品、竞品、用户情绪、产品属性、身份认同、认知空位和传播动作等核心链路，但 `Positioning` 尚未作为独立策略模块显式登记。同时，ECS 服务器目录仍是手工部署目录，不是 Git 仓库，需要切换为 GitHub 标准发布形态。

## 问题分析

1. `Positioning` 作为汽车营销咨询中非常关键的车型定位判断，不应只隐含在“认知空位”和 Gap 逻辑中。
2. 服务器目录若不纳入 GitHub 版本链路，后续发布无法稳定追溯，也不利于回滚。
3. 云端演示环境需要与本地确认版本保持一致，避免出现“本地已修复、云端仍旧版”的情况。

## 技术方案

1. 将 `Positioning` 显式加入 MMN Strategy Model 模块列表。
2. 更新系统说明文档与模型方法论文档，明确 Positioning 的作用。
3. 保持现有页面和接口不做大规模重构。
4. 本地测试通过后，将当前稳定版本提交到 GitHub。
5. 将 ECS 项目目录整理为从 GitHub 拉取代码的标准发布形态，保留服务器 `.env` 和 Docker volume 数据。
6. 使用 `deploy.sh` 重建云端服务并执行云端模型能力测试。

## 功能实现

1. 更新 `server.py` 中的 `MMN_STRATEGY_MODEL.modules`。
2. 更新 `README.md` 的 MMN Strategy Model 说明。
3. 更新 `docs/mmn-strategy-model.md` 的核心模块和标准策略流程。
4. 更新 `cloud_model_check.md` 中 Positioning 风险说明。
5. 归档本次研发记录。
