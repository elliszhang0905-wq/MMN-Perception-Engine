# 全量细分市场销量预警实施计划

## 目标

将现有“单一中型及中大型纯电轿车 Demo”升级为覆盖懂车帝销量榜全部上汽车型的动态管理预警。点击任一上汽车型时，自动切换到该车型所属的“车身形式 × 尺寸级别 × 能源驱动形式”细分市场，并同步展示该市场总销量、市场车型销量中位数、所选车型销量、中位数相对位置及红黄绿灯号。

## 已确认的现状

- 懂车帝公开页面支持轿车、SUV、MPV的尺寸分榜，以及纯电动、插电式混动、增程式能源分榜。
- 榜单采用滚动分页加载；2026年6月纯电动榜完整加载为195款，现有自动采集只保存每榜前10款。
- 当前MMN快照仅有216条最新月记录、21个可识别上汽车型，不能代表懂车帝完整榜单。
- 尺寸与能源不是一个组合URL，需要以车型ID对尺寸榜和能源榜做集合交叉。

## 统一口径

1. 车型主键使用懂车帝 `series_id`，车型名只作为展示与别名辅助。
2. 细分市场主键为 `body_type + size_class + energy_type`。
3. 同一车型在尺寸榜、能源榜出现时只计一次销量；不同榜单销量不相加。
4. 市场总销量为该细分市场全部车型当月零售量之和。
5. 市场基准为该细分市场全部车型销量中位数，不排除上汽车型。
6. 初始灯号规则：低于中位数80%为红灯；中位数80%—120%为黄灯；高于中位数120%为绿灯。阈值作为显式配置保存，后续可由管理层调整。
7. 未进入纯电、插混或增程榜的车型暂标记为“非新能源（燃油/油混待车型主数据复核）”，不伪造懂车帝不存在的能源分类。
8. 双旗舰模型只验证锁定事实包和计算结果，不改写销量、市场归属、中位数或灯号。

## 实施阶段与验收门

### 阶段一：全量采集

- Playwright滚动至榜单车型数连续稳定，保存完整渲染榜单。
- 每个榜单排名必须从1连续递增，不允许只保存Top10后标记完成。
- 采集结果保存 `series_id`、车型、厂商/品牌、车身尺寸、价格、销量、榜单类型和月份。

验收：纯电动榜可重复得到195款；所有配置榜单均记录完整性状态和行数。

### 阶段二：车型与细分市场归一

- 以 `series_id` 合并尺寸榜和能源榜。
- 建立上汽集团品牌/厂商白名单并保留匹配原因。
- 产出每个上汽车型的唯一细分市场及该市场完整车型池。

验收：每个上汽车型都有唯一车型ID、唯一尺寸级别、唯一能源形式；冲突记录进入数据质量清单而不是静默覆盖。

### 阶段三：动态预警计算

- 为每个细分市场计算总销量、车型数、中位数和80%/120%边界。
- 为每个上汽车型计算销量/中位数倍率、上下差额与红黄绿灯号。
- 灯号按车型所属市场动态计算，不复用其他车型市场数字。

验收：至少覆盖轿车、SUV、MPV及纯电、插混、增程的跨市场算例。

### 阶段四：管理层交互

- 左侧列出全部上汽车型；点击车型后同步更新市场标签、市场总销量、市场中位数、车型销量、倍率和灯号。
- 固定市场指标明确标注“所选车型所属市场”，车型指标明确标注车型名。
- 数据不完整时显示灰色“数据质量待补”，不得错误显示绿色。

验收：连续点击不同尺寸和能源形式的车型，市场总销量必须随归属市场变化；同市场车型可共享市场总量，但车型销量和倍率必须变化。

### 阶段五：验证与发布门

- 双旗舰模型基于同一锁定全量证据包独立复核。
- 任一路未通过时管理结论不发布，但确定性事实数字仍可查看。
- 执行单元测试、全量发布门、真实浏览器逐车切换和控制台检查。

验收：双旗舰模型均通过；无供应商名称前台泄露；无浏览器运行时错误。

## 风险控制

- 懂车帝滚动接口与签名随页面变化：不破解签名，仅通过公开页面正常滚动加载并校验完整性。
- 同车系多能源版本：优先使用懂车帝独立车系ID；出现一个ID跨能源榜时标记冲突并停止自动灯号。
- 上汽合资品牌边界：采用显式白名单，不依靠“上汽”字符串模糊匹配。
- 榜单月度修订：以榜单类型、车型ID、月份做幂等更新，保留抓取时间与事实指纹。
