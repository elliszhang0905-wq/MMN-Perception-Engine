# 车型资产一致性与MMN页面输出能力修复

## 研发日期

2026-06-28

## 版本号

beta 1.01

## 需求背景

本次更新来自产品联调过程中暴露出的基础逻辑问题：蒸馏后的达人资产需要进入对应平台达人库；小红书 / 抖音等平台蒸馏资产需要可被 MMN 模型复用；车型库必须保证品牌、车型、别名、空格和中英文写法的一致性；每个功能页都应具备 MMN 分析和输出能力，不能出现有数据但页面空白的情况。

同时，用户明确要求本次完成后进行 beta 1.01 版本更新，并保持本地与服务器版本同步。后续每一次更新都必须有一份正式文档记录更新内容。

## 问题分析

1. 部分车型别名没有统一归一，导致同一车型被拆成多个车型，例如“极狐贝塔S3”和“极狐 贝塔 S3”。
2. 部分品牌和车型关系缺少强约束，导致车型可能出现在错误品牌下，例如荣威 i5 进入宝马车型列表。
3. 中英文品牌别名未统一，例如“极氪”和“ZEEKR / ZEEKER”并存。
4. PHEV / 插电混动等能源写法没有合并到同一车型家族。
5. 垂媒正反向矩阵在选择周期后，表格行可能显示非当前周期数据。
6. 内容资产蒸馏后，达人资产没有明确进入平台达人库。
7. “打法知识库”页面跟随策略驾驶舱车型，但页面没有显示来源，容易被误解为该页可独立选择车型。
8. “人工结论学习”页面原先缺少品牌 / 车型下拉和 MMN 草案生成能力。

## 技术方案

1. 建立更严格的车型本地归一规则，优先处理高风险品牌和别名：荣威、宝马、极狐、大众、极氪。
2. 品牌车型下拉按“品牌 + 车型家族 + 能源类型”聚合，避免同一车型因为空格、中英文或后缀差异重复出现。
3. 后端车型识别接口支持双模型交叉验证和强制复核，返回统一 canonical key。
4. 垂媒矩阵严格按当前选择周期取数，不再回退到最新可用周期。
5. 蒸馏后的创作者画像按平台合并进入达人库。
6. 人工结论学习页增加品牌 / 车型选择和 MMN 生成能力，融合声量、正反向、车型判断和 RAG 资料。
7. 打法知识库页增加“当前车型来源”状态条，说明当前车型来自策略驾驶舱。
8. 增加应用版本常量，服务端 `/api/health` 返回 beta 1.01，前端版本架构页显示 beta 1.01。

## 功能实现

1. 车型资产一致性
   - 统一“荣威i5 / 荣威 i5”和“宝马i5 / 宝马 i5”的品牌边界。
   - 统一“极狐贝塔S3 / 极狐 贝塔 S3”等空格差异。
   - 统一“大众途观L PHEV / 途观L 插电混动”。
   - 将“ID.ERA 8X / ID ERA 8X / ID.ERA 9X / ID ERA 9X”归属大众。
   - 统一“极氪 / ZEEKR / ZEEKER”别名。

2. 内容资产与达人库
   - 小红书、抖音等平台蒸馏后的达人资产进入对应平台达人库。
   - 博主切换时，样本拆解、能力画像和 RAG 知识片段按当前达人同步刷新。

3. MMN 输出能力
   - 人工结论学习页支持品牌和车型选择。
   - 只要存在声量、正反向、车型判断或 RAG 任一数据，即可生成 MMN 草案；无直接数据时输出缺口建议，不再空白。
   - 打法知识库页显示“当前车型来源：策略驾驶舱”，并展示品牌和车型。

4. 版本同步
   - 前端缓存版本更新为 `beta-1.01`。
   - 前端版本架构页显示当前版本 `beta 1.01`。
   - 后端 `/api/health` 返回 `version: beta 1.01`。
   - `package.json` 更新为 `1.0.1-beta`。
   - `VERSION.md` 与 `README.md` 明确当前本地与服务器同步基线，以及以后每次更新必须归档。

## 版本变更说明

beta 1.01 是一次基础一致性修复与产品可解释性增强版本。该版本重点不是新增单一页面，而是修正 MMN 汽车营销引擎的底层资产口径：车型库、达人库、蒸馏资产、页面输出和版本记录必须形成闭环。

该版本兼容现有本地数据、SQLite 数据库、导入文件和云端部署脚本，不改变既有接口路径。

## 后续计划

1. 在所有功能页继续补齐“当前分析对象 / 数据来源 / MMN输出依据”的状态展示。
2. 将车型资产归一规则沉淀为可维护的车型资产表，而不是长期依赖前端规则。
3. 建立每次发布后的自动健康检查：本地版本、服务器版本、前端资源版本和数据库备份状态必须一致。
4. 后续每一次功能更新都新增研发档案，避免只改代码没有版本记录。
