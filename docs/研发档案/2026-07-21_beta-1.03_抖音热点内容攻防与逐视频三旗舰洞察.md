# beta 1.03 抖音热点内容攻防与逐视频三旗舰洞察

## 研发信息

- 研发日期：2026-07-21
- 版本：`beta-1.03-20260721-douyin-content-defense-1`
- 版本类型：大版本功能升级

## 业务目标

在保留抖音热门视频/话题、24小时/7天/30天榜单与品牌车型雷达的前提下，将单条视频从“传播指标模板”升级为真实、可追溯、可降级的多模态内容洞察，并与 E7X 属性 NSR、竞品差值和白皮书产品事实共同形成热点内容防线。

## 关键决策

1. 只在用户点击某条视频时启动取证与三旗舰分析，每日榜单采集不自动消耗该部分 token。
2. 三路分析使用同一版本证据包且独立运行，交叉校验保留多数一致、少数异议和关键冲突，不采用简单投票。
3. 原页可访问性与后台媒体可读性分开记录；缺失视频本体、ASR、OCR 或视觉证据时明确降级。
4. 客户界面只显示 MMN 中性能力名称与可读限制，内部运行记录继续保留路由、版本、错误与原始结构化输出。
5. 线索仅作结果校验；不把热度、评论 NSR 或时间相关直接写成需求、销量或线索因果。

## 实现范围

- 逐条视频证据包、内容指纹、异步状态、缓存、重试、刷新/重启恢复和组织/版本隔离。
- 字幕/ASR、OCR、关键镜头/视觉结构、标题、评论、品牌车型识别与传播指标归一化。
- 三路独立运行、严格 Schema 校验、交叉质检、分歧与人工复核。
- E7X 15 属性 NSR 与白皮书候选页定向扩展；白皮书缺失的属性不允许用常识补齐。
- 榜单卡片中的生成/重试、进度、独立洞察、证据、三路状态、分歧和分析边界。
- 本地 CDP 与服务器端 Chromium 双模式原页取证，遇登录、验证码或风控即降级。

## 数据保护与回滚

- schema 只通过 `CREATE TABLE IF NOT EXISTS` 等向前兼容方式增加，不重置旧表。
- 视频洞察产生新记录，不更改原榜单、品牌车型人工复核、项目快照或用户业务数据。
- 发布前保留本地和 ECS 的代码、`.env` 与持久数据备份；回滚时代码与对应时点数据成对恢复。

## 验收边界

自动测试覆盖完整三路、单路失败、共同证据不一致、视频不可读、白皮书缺属性、弱势属性、插件错误、缓存幂等、刷新恢复、租户隔离和客户侧信息安全。真实验收必须另外包含原页播放、视频本体证据、三路运行、最终持久化洞察、1440/390 界面、网络、控制台、日志与现有六榜回归。
