# 2026-07-02 beta 1.01 内容资产自动抓取逻辑

## 更新目标

内容资产中心不再表现为“上传 Excel 的文件收容页”，而是围绕当前本品和核心竞品自动生成抖音 / 小红书抓取任务。用户在页面中选择或填写车型后，每个平台、每个车型槽位都应该进入采集流程，并将采集结果沉淀为内容资产。

## 页面逻辑

- “本品 + 竞品”车型预设仍然是内容资产归因的源头。
- 抖音和小红书矩阵不再显示“上传 / 等待上传 Excel”。
- 每个槽位显示两个动作：
  - `开始抓取`：按当前车型生成搜索词，打开对应平台采集页。
  - `同步结果`：读取 Chrome 采集插件最新导出，并按当前平台和车型槽位写入内容资产。
- 抓取状态分为：
  - 等待自动抓取
  - 采集任务已打开
  - 已同步内容条数

## 数据流

1. 页面根据 `本品 / 竞品 1 / 竞品 2 / 竞品 3` 生成平台抓取任务。
2. 通过已有 `/api/social-plugin/open` 打开抖音或小红书搜索页。
3. 通过已有 `/api/social-plugin/import-latest` 读取插件最新导出。
4. 系统将导出的内容条目补充 `assetPlatform`、`assetSlot`、`assetRole`、`assetModel`，进入车型内容资产看板。
5. 同步结果中识别出的达人画像继续进入对应平台达人库。

## 修正点

- 取消内容矩阵中的隐藏文件上传入口。
- 取消“等待上传 Excel”“已上传文件”等文案。
- 移除此前对 `社媒助手` / `pluginExportPath` 内容资产的前端过滤，允许明确归因到平台和车型槽位的自动抓取结果进入内容库。
- 页面资源版本更新为 `beta-1.01-auto-crawl-1`，避免浏览器缓存旧逻辑。
