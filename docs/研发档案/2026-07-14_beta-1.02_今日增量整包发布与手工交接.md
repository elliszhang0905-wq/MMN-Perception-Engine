# beta 1.02｜2026-07-14 增量整包发布与手工交接

## 发布目标

将上一生产版本之后完成的 MMN 增量能力作为同一批次同步到 GitHub 与 ECS，确保代码、数据资产、测试、研发档案、发布记录和交接手册保持一致。本批次不改变 MMN 与 Sales Credo 的产品边界。

## 发布范围

1. 品牌传播穿透
   - 增加异步采集进度、阶段状态和商用车实体隔离。
   - 本品与最多 5 个竞品按同一传播证据口径分析。
2. 决策驾驶舱与竞品格局
   - 整体平台 NSR 改为车型 × 平台指纹矩阵。
   - 修复正反向排名趋势数字碰撞和缺失周期错误连线。
3. 社媒趋势中心
   - 采集改为后台任务并支持自定义日期、平台诊断和结果恢复。
   - 竞品从 MMN 品牌车型库按“品牌 → 车型”选择，最多 3 台。
   - 正向热度明确展示本品 Benchmark；风险 KPI 气泡下钻到具体负向内容和原文。
4. 懂车帝销量
   - 按真实数据月份和文件签名选择最新 feed，修复旧文件遮挡与缓存不刷新。
   - 同步 2026 年 6 月销量 feed 与 RAG；登录受限时合规停止，不保存 Cookie、Token 或账号信息。
5. 抖音与小红书内容能力
   - 新增抖音热点实体识别、双模型一致性、人工复核、快照和采集任务能力。
   - 新增小红书内容热度排名与品牌/车型雷达演示，并保留“社媒证据不等于市场需求”的边界提示。
6. 发布保障
   - 新增和扩展 Python、JavaScript、浏览器发布门禁；前端资源使用新的缓存版本。

## 手工交接步骤

### 本地

1. 使用完整文档运行时执行全量 Python 测试；系统 Python 缺少 `python-docx` 时，不得误判为业务失败。
2. 执行全部 `tests/test_*.js`。
3. 执行 `bash scripts/release_gate.sh`，要求 `failed: []`、`runtimeErrors: []`。
4. 检查暂存区不含 `.env`、密钥、Cookie、Token、日志、PID 和 `output/playwright/`。

### 服务器

1. 在 `/opt/mmn-perception-engine` 创建代码归档，保留当前 `.env` 与运行数据。
2. 从已推送的 Git 提交生成归档并同步到无 `.git` 的服务器发布目录。
3. 执行 `MMN_SKIP_GIT_PULL=true bash deploy.sh`；部署脚本会再创建运行数据备份。
4. 验证 `/api/health`、首页、版本化 `app.js`、关键新增前端资源、容器状态与近期错误日志。
5. 运行 `scripts/test_mmn_cloud.sh http://121.40.60.90`，并手工检查社媒趋势中心关键路径。

## 回滚方案

- 代码：恢复本次部署前的服务器代码归档。
- 数据：使用 `scripts/backup.sh` 产生的同批次数据备份恢复。
- 执行：恢复代码与数据后重新运行 `MMN_SKIP_GIT_PULL=true bash deploy.sh`，再验证健康接口、首页资源和日志。
- 本批次没有需要单独执行的破坏性数据库迁移；应用初始化继续使用向后兼容建表/补列逻辑。
