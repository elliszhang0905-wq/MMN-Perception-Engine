# MMN Eval v0.1 离线评测基础能力

## 研发日期

2026-07-17

## 版本号

beta 1.02 / MMN Eval `mmn-eval-v0.1`

## 需求背景

MMN 已具备多模型复核、证据 ID、冲突转人工、策略知识资产和局部 Langfuse 观察器，但缺少统一的案例合同、质量评分、硬门禁、人工复核队列和版本回归机制。本次先建立独立离线评测域，不改变现有产品页面、接口、数据库和模型调用路径。

## 问题分析

- 既有单元测试主要验证工程行为，不能统一回答一次输出是否达到 MMN 策略交付标准。
- 既有评审记录数量有限，尚未形成版本化金标准案例集。
- 缺失数据、平台指标越界、证据引用和模型复核规则分散在不同业务模块。
- Prompt、模型或 RAG 版本调整后，缺少 baseline/candidate 成对回归报告。
- 当前核心文件存在其他未提交改动，因此本次不修改 `server.py`、机会地图、管理层看板和前端文件。

## 技术方案

- 新增标准库实现的 `mmn_eval` 独立包，分为合同、Rubric、评分器和运行器四层。
- 采用“确定性硬门禁优先、质量分其次”的判定顺序；硬门禁不可被总分抵消。
- 五个维度合计 100 分；缺失维度保持 `null`，按已观测权重归一化展示得分，同时强制转人工。
- JSONL 案例与输出均执行严格边界校验；缺失案例、额外案例和不完整 baseline 均阻断严格版本比较。
- 维度评分强制记录 `gradingSource`，只接受人工、独立 Judge 或合成夹具，避免候选模型自评分进入 Eval。
- CLI 支持单版本运行和 baseline/candidate 对比，输出 JSON 与 Markdown。
- 使用无敏感信息的合成种子集证明通过、人工复核和失败三条路径。

## 功能实现

- Rubric 版本：`mmn-eval-v0.1`。
- 暂定阈值：80 分通过、65–79.99 分人工复核、低于 65 分失败。
- 硬门禁覆盖：编造事实、未知证据、缺失写零、多模型不完整、车型配置三模型不完整、平台指标越界、来源独立性不足、声明类型缺失。
- 车型配置固定要求 Qwen、DeepSeek、Kimi 全部完成并具有合法共同证据。
- 版本对比识别状态下降、新硬门禁、5 分及以上分数下降、候选缺失案例和已修复案例。
- 人工复核报告给出案例 ID、任务类型、得分和触发原因；MMN 项目负责人保留最终裁决权。

## 修改模块

- `mmn_eval/`：评测合同、Rubric、评分器和运行器。
- `scripts/run_mmn_eval.py`：离线 CLI。
- `data/eval/`：10 条合成种子案例与对应输出。
- `tests/test_mmn_eval_*.py`：合同、评分、版本比较和种子集测试。
- `docs/mmn-eval.md`：操作与人工标注规范。
- `docs/superpowers/plans/2026-07-17-mmn-eval-v0.1.md`：实施计划。

## 版本变更说明

本次为本地新增能力，保持现有 MMN 信息架构、导航、业务数据、模型路由和服务器版本不变。评测报告暂用于内部校准；在人工负责人冻结 Rubric 与阈值、真实案例集形成、全链路 Trace 接入前，不作为生产发布的唯一依据。
