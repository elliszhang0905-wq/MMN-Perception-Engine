# MMN 系统状态包自动维护机制研发记录

## 研发信息

- 研发日期：2026-07-20
- 版本号：beta 1.02
- 研发团队：MMN研发团队

## 需求背景

项目需要一份可持续维护、可由代码差异自动约束的当前状态说明，避免功能、数据链路、权限或部署发生变化后，项目说明仍停留在旧状态。

## 问题分析

仓库此前已有完整的产品边界、研发档案和发布门禁规则，但没有统一的当前系统状态入口，也没有检查业务变更是否同步更新该入口。现有仓库没有持续集成配置，因此本轮只能先建立本地固定命令与永久执行规则。

## 技术方案

1. 在根目录规则文件追加系统状态包永久维护约束与固定汇报格式。
2. 建立根目录 `MMN_CURRENT_STATE.md`，按真实代码记录技术栈、页面、功能真实性、数据链路、接口、存储、权限、风险和产品边界。
3. 使用无新增依赖的 Node 脚本读取 Git 差异，区分业务/部署变更与测试、普通文档、锁文件。
4. 在 `package.json` 固定暴露 `npm run check:mmn-state`，并支持工作区、首次提交和指定 Git 基线。

## 功能实现

- 相关业务或部署文件发生变化而状态包未更新时，检查返回非零退出码，并列出触发文件。
- 仅有测试、普通文档、锁文件、运行数据/产物或状态机制自身变化时不误报。
- 指定基线支持命令参数 `--base` 和环境变量 `MMN_STATE_BASE_REF`。
- 新增独立脚本测试覆盖无改动、忽略项、缺失状态、首次提交和指定基线。

## 修改模块

- 根目录研发规则：`AGENTS.md`
- 当前系统状态：`MMN_CURRENT_STATE.md`
- 差异检查：`scripts/check_mmn_state.mjs`
- 固定命令：`package.json`
- 检查器测试：`tests/test_check_mmn_state.mjs`

## 测试结果

- `npm run test:mmn-state`：通过，覆盖无改动、忽略项、缺失状态、首次提交、删除源码和指定基线。
- `npm run check:mmn-state`：通过。
- `npm run check:mmn-state -- --base HEAD`：通过。
- `git diff --check`：通过。
- `npm run release:gate`：通过；147 个 Python 回归测试通过，两组真实浏览器门禁均无失败项和运行时错误，全表面门禁另确认无失败响应。

## 版本变更说明

本次只建立文档、规则、检查脚本和本地命令，没有修改业务功能、页面 UI、路由、数据模型、接口、环境变量或现有产品结构。

## 后续计划

- 仓库建立持续集成后，将 `npm run check:mmn-state -- --base <合并请求基线>` 接入必过门禁。
- 后续每次相关开发按永久规则同步维护状态包，并在最终汇报中固定披露检查结果。
