# MMN 产品边界与营销模块打磨研发记录

## 研发日期

2026-07-06

## 版本号

v1.0-beta.1.01

## 需求背景

MMN Perception Engine 需要进一步明确自身作为汽车营销策略系统的产品边界。系统当前服务对象为车企品牌、市场部门、车企代理公司和汽车垂直 MCN，核心能力应围绕车型策略、竞品传播分析、达人蒸馏、内容 brief、脚本生产、品牌/高管 IP 蒸馏、市场周报和策略报告输出展开。

Credo 属于独立产品线，面向经销商、销售顾问和门店管理者。两条产品线可共享底层车型知识库、竞品资料和部分数据结构，但前端产品、功能路径、交付口径和商业化模型必须独立设计。

## 问题分析

本次检查发现，MMN 既有页面文案、策略输出模板和部分规则词表中存在少量偏销售接待、门店承接或销售顾问场景的表达。这些内容容易造成 MMN 与 Credo 的产品边界混淆，不利于后续构建面向品牌市场和内容策略团队的营销智能体矩阵。

## 技术方案

1. 对前端页面、前端渲染脚本、后端策略输出模板和产品文档进行边界审查。
2. 将偏销售接待、门店、销售顾问语义的表达替换为品牌传播、内容 brief、意向线索、客户策略汇报等 MMN 语境。
3. 保留产品边界文档中对 Credo 的说明，作为后续研发的隔离约束。
4. 在 MMN Strategy Model 中补充内容 brief、脚本生产、达人蒸馏、竞品传播分析、品牌/高管 IP 蒸馏、市场周报、策略报告输出和营销智能体矩阵预留模块。

## 功能实现

- 优化决策驾驶舱、内容资产、策略报告、高管蒸馏等模块的用户侧文案。
- 清理策略生成、PPT 大纲、报告导出中的销售承接类表达。
- 更新 MMN Strategy Model 模块清单，明确未来模块化方向。
- 更新 README 与交接手册，强化 MMN 与 Credo 的产品边界。

## 修改模块

- 前端页面结构：`index.html`
- 前端交互与策略渲染：`app.js`
- 后端策略模型常量与输出模板：`server.py`
- 产品说明文档：`README.md`
- 交接手册：`docs/HANDOFF_QWEN_AGENT.md`
- 策略模型文档：`docs/mmn-strategy-model.md`

- 已完成 `server.py` 语法检查，通过。
- 已完成 `app.js` 语法检查，通过。

## 版本变更说明

本版本属于产品边界和文案结构打磨，不改变现有数据库结构、不新增大功能、不删除既有模块。核心变化是把 MMN 的表达和模块定义收敛到品牌市场、内容策略、达人资产、竞品传播和策略报告输出。

## 后续计划

1. 将内容资产中心继续拆分为达人资产、内容 brief、脚本生产和能力蒸馏子能力。
2. 将决策驾驶舱与车型策略报告输出进一步收敛为车型策略智能体。
3. 为竞品传播分析、市场周报、高管 IP 蒸馏预留独立智能体边界。
4. Credo 相关销售顾问和门店接待能力继续保持在独立产品线内设计，不进入 MMN 默认导航与交付路径。
