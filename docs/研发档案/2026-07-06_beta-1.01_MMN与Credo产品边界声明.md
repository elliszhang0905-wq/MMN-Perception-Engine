# MMN 与 Credo 产品边界声明

## 研发日期

2026-07-06

## 版本号

beta 1.01

## 需求背景

随着 MMN Perception Engine 与上汽行 Sales Credo 两条产品线同时推进，需要明确两者的产品定位、用户对象、功能边界和商业化路径，避免后续迭代中出现功能混装、页面信息架构混乱或交付话术混用。

## 问题分析

MMN 与 Credo 可以共享底层车型知识库、竞品资料和部分数据结构，但两者服务对象不同：

- MMN 面向车企品牌、市场部门、车企代理公司和汽车垂直 MCN。
- Credo 面向经销商、销售顾问和门店管理者。

如果将 Credo 的门店销售功能直接放入 MMN，或将 MMN 的营销策略、达人蒸馏、内容生产和品牌传播能力直接放入 Credo，会造成产品定位不清、权限模型混乱、前端路径复杂和商业化模型失焦。

## 技术方案

本次不修改业务代码，仅通过项目文档、交接手册和智能体规则入口固化产品边界：

1. 在 MMN 项目规则中增加产品边界要求。
2. 在 MMN 交接手册中增加 MMN 与 Credo 的产品边界章节。
3. 在 MMN README 中补充产品边界说明。
4. 在 Credo 交接手册和 README 中补充对称边界说明。

## 功能实现

已明确以下规则：

- MMN 与 Credo 是两条独立产品线，不应混成一个系统。
- MMN 聚焦营销策略、达人蒸馏、内容生产、品牌传播与报告输出。
- Credo 聚焦本品卖点、竞品对比、销售攻防话术与到店接待辅助。
- 两者可以共享底层车型知识库、竞品资料和部分数据结构。
- 两者的前端产品、用户权限、功能路径、交付话术、页面信息架构和商业化模型必须独立设计。
- 禁止把对方业务功能直接塞进本项目。

## 后续计划

1. 后续任何涉及 MMN 与 Credo 的共享能力开发，必须先说明共享的是底层资料、数据结构还是业务功能。
2. 若共享车型知识库或竞品资料，应以导出包、API 或独立共享服务方式接入，不直接互相侵入前端业务路径。
3. 发布服务器前，应检查本次变更是否只影响对应产品线。
