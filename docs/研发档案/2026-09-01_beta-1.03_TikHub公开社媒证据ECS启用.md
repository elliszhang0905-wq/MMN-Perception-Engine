# beta 1.03 TikHub 公开社媒证据 ECS 启用

## 研发日期

2026-09-01

## 版本号

`beta-1.03-20260901-tikhub-social-evidence-1`

## 需求背景

将主线中已经具备预算、组织隔离、持久化队列与证据边界的公开社媒证据 V2 能力，在 ECS 生产环境受控启用，并同步 GitHub 主线。客户界面继续使用中性能力名称，不暴露底层数据服务名称。

## 问题分析

生产环境已有非空 TikHub 密钥，但 V2、独立 Worker 模式和 Compose profile 均未启用，因此代码存在不等于生产可用。直接从当前主工作区发布还会把大量无关未提交代码和业务数据带入生产，不能接受。

## 技术方案

- 从最新 `origin/main` 建立独立干净工作树，只提交本次版本、配置示例、状态包、测试契约与发布文档。
- 仓库示例配置保持失败关闭；生产仅通过受保护的 `.env` 设置 V2、外部 Worker 模式和 `social-evidence-v2` profile。
- 以精确 Git 提交归档部署 ECS，不复制本地数据库、备份或主工作区未提交内容。
- 部署前备份源码、环境配置与持久数据，并记录归档 SHA-256，保留可恢复的上一个运行版本。
- 真实验收只允许一次、最多一次外部请求的最小抖音任务；不自动重试，不把传播证据写成成交证明。

## 功能实现

- 服务版本升级到 `beta-1.03-20260901-tikhub-social-evidence-1`。
- `.env.example` 增加空的 `COMPOSE_PROFILES` 默认值，继续保持 V2 与 Worker 默认关闭。
- 独立 Worker 覆盖镜像默认 HTTP 健康检查，改用进程型检查，避免后台进程因不监听 Web 端口而被误判。
- 发布版本测试将泰国看板静态资源版本与应用运行版本拆分，避免无关静态资源被错误换版。
- 状态包与发布工单同步记录生产启用条件、计费边界和零数据迁移范围。

## 版本变更说明

本版本不新增客户页面，不迁移业务数据库，不修改既有证据模型。发布影响仅为生产运行版本标识和受控开启现有 V2 Worker；关闭三个生产环境开关并恢复发布前归档即可回退。
