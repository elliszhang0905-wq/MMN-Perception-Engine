## 2. 目标与业务价值

解决“某个判断或建议分歧，导致整个品牌卡片只显示无法输出”的问题。在不改变现有基本结构的前提下，每次返回有证据支持的可用内容、明确争议和可执行的下一步；没有可靠证据时允许没有结论。

目标不是保证三路意见相同或保证每张卡片都有建议，而是：

1. 有效证据不因无关字段分歧被一并隐藏。
2. 事实、传播解释、条件化建议、未知分别有清晰的发布资格。
3. 分歧可定位到具体声明及来源，人工处理后可追溯。
4. 本地与服务器运行同一规则版本，分别证明部署安全和真实功能可用。

## 5. 目标输出及发布规则

### 5.1 五类分歧

| 内部分歧类型 | 判别标准 | 客户侧结果 |
| --- | --- | --- |
| `label_overlap` | 冻结分类词典明确允许并存，且不改变同一声明的对象、时间、范围与方向 | 有支持的主次标签；无法确定主标签时不强行排序 |
| `interpretation_conflict` | 同一事实被赋予不同传播意义，或存在方向性冲突 | 保留事实；冲突判断标“判断待确认”，说明争议焦点 |
| `action_preference` | 事实与前提相容，分歧仅涉及行动选择或优先级 | 保留判断；满足行动合同者列为条件化备选，不冒充推荐路径 |
| `evidence_conflict` | 来源之间存在未解释的数值、实体、日期、版本或事实冲突 | 阻断依赖该冲突的声明与动作，展示冲突及补证要求 |
| `execution_incomplete` | 超时、权限/额度错误、不可解析 JSON、缺行或无效字段 | 标明复核未完成；可展示独立可核验的来源事实，不发布未经完成复核的策略 |

分类不明一律进入 `unresolved`，不得默认归入“只是表达差异”。非互斥词典必须版本化并有正反例，例如新品发布与技术传播可并存，但加强与减弱、增投与停投不能被同义化。

### 5.2 按层输出，不以整行状态控制全部内容

每条声明都绑定自己的 evidenceIds、来源锚点和依赖声明；行状态仅用于摘要。禁止前端 `status != aligned` 就隐藏所有正文。

1. **事实层**：优先确定性提取冻结来源中的事件、日期、样本计数或可读引文。引用存在不等于语义成立；模型改写须逐声明核验。仅观察到标题或来源自述时，写“该来源提及/宣称”，不得升级为客观事实确认。
2. **判断层**：以已经通过证据核验的声明为输入，记录推理链、替代解释、反对证据和范围。首轮可提出候选声明，再进行声明级复核；任何未解决的实质反对意见都阻断该声明的确定性发布。无关标签或动作分歧不得阻断它。不能仅按文本相似度判定语义等价。
3. **行动层**：依赖的事实与判断全部可用，且具有适用条件、成本/风险、领先指标、结果指标、验证阈值、观察窗口、停止条件和不做事项，才能进入候选动作。推荐路径还需理由、取舍及授权审核；缺字段即“待补证”，不填虚构数字。
4. **未知层**：指明缺什么、影响哪项判断、由谁补证或复核；不以通用建议代替缺口。

同一证据被三路共同引用仍保留为“共同引用”属性，但不能单独决定事实真伪；不同有效来源支持同一声明时可分别保留，不能仅因 evidenceIds 交集为空就认定事实不可用。来源独立性必须另算。

复核未完成时只交付已有确定性来源事实及未知，不将两路结论自动标成共识。人工可以裁决解释和选择动作，但不能豁免引用、隔离、来源冲突和汽车方法论硬门禁。安全、质量指控、法律/监管、购买转化因果、重大预算动作须继续走相应严格核验；本单不新开豁免路径。

### 5.3 逐竞品合同

涉及“本品相对竞品”的声明必须同时有双方匹配证据，比较时间窗和口径一致。只有竞品证据时可陈述竞品自身行为，不得推断本品弱势。不能由传播主题重合直接断言消费者发生品牌替代。

### 5.4 页面表达

沿用原卡片结构，按内容资格展示“已确认信息 / 传播判断 / 可选动作 / 待确认事项”。无内容的层不占大空白。卡片主点击继续定位品牌证据，复核操作使用同区块独立按钮或既有侧面板，禁止嵌套 button。

状态文案：`结论可用`、`部分结论可用`、`仅展示来源信息`、`待人工复核`、`证据待补充`、`复核未完成`。相应原因以中性中文展示，不输出 judgement、primaryIntent、provider 错误或模型名称。

原“三路一致/置信度85%”不再作为 v4 的默认质量标签。改显示证据条数、独立来源数量、复核完成情况和确定/待验证边界；自报 confidence 仅内部审计保留，不能代表正确率。v3 历史结果标明历史规则，原内容不被悄悄重算成 v4。

## 6. 工程合同

### 6.1 版本与字段

新增 `schemaVersion=brand-penetration-analysis-v4`、`ruleVersion=brand-review-layered-v1`；既有 `brandConclusions`、`pairwiseConclusions` 和身份字段保留。

每条声明最少包含：`claimId`、`kind(fact|inference|hypothesis|unknown)`、`text`、`evidenceRefs`、`dependsOn`、`publicationStatus`、`reasonCodes`。`evidenceRefs` 绑定 evidenceId、sourceFingerprint、可回读的 quote/span、来源时间与对象范围。模型提交的 verdict 只是候选，不是可信核验结果。

可信服务端核验记录包括：`claimId`、`evidenceFingerprint`、`ruleVersion`、`reviewVersion`、支持/反对/未完成状态、核验依据、执行身份与时间、产物哈希。请求体不得伪造这些身份或 verdict。

卡片输出包含 `facts[]`、`insights[]`、`actionOptions[]`、`disputes[]`、`unknowns[]`、`reviewCoverage`；动作明确 `allowExecution=false`，本单不调用投放或执行接口。兼容性降级不得把部分通过的 v4 拼成 v3 aligned。

### 6.2 持久化与授权

在 MMN 统一数据根内新增本模块专属追加式存储，不改写历史快照；建议新建 `brand_review_versions`、`brand_review_decisions` 表。创建表只在显式初始化/迁移阶段执行，关闭模式下不偷偷建表、写 trace 或更新旧记录。

隔离键包含认证的 orgId、edition、projectId、snapshotId、evidenceFingerprint、promptVersion、ruleVersion、reviewVersion；品牌/逐竞品身份作为对象键。人工裁决固定为采纳、修改、否决，必须记录原因、修改前后值、actorId、serverTime、expectedVersion、idempotencyKey。客户端传入 orgId 不得覆盖服务端认证范围。

同幂等键同内容返回原结果；同键不同内容、过期版本返回冲突。新增一次裁决生成新版本及被替代关系，旧版本保持可读。权限不足返回 403，越租户对象不返回其内容。前台只消费脱敏投影，原始提示词、三路正文、技术错误不直接进入页面/导出。

人工改写必须重新运行该声明及依赖项的硬门禁。人工裁决不会自动训练模型、改变提示词、修改全局规则或发布 Learning；规则沉淀仅生成候选，另行签审和回归。

### 6.3 缓存、并发与重试

- 新规则不复用旧规则 verdict；证据、项目、时间窗、规则或提示词变化生成新版本。
- 刷新页面、查看历史、切换卡片不得触发付费重跑；只读取有效缓存。
- 首轮三路完全盲审。格式修复仅包含自身无效项、原冻结证据和校验错误，不输入其他路答案；成功行不可被修复结果覆盖。
- 每路最多首次 1 次加修复/可重试失败 1 次；一个品牌组合一轮最多 6 次调用，重试计入总额度，不按品牌无限放大；在既有更低上限与本单上限之间取低值。
- 绝对截止时间不超过 300 秒，单调用不超过 120 秒；所有排队、调用与修复共用截止时间并可取消。权限、额度、明确不可重试的业务错误不自动重试；不因观点不同自动重跑。
- 本版本不增加自动第四路裁决调用；确定性规则无法消除的实质分歧进入人工复核。若实现需要额外模型裁决，必须另报调用预算和质量依据，不隐含增加。
- 任务取消、项目切换或旧版本迟到时不得覆盖新结果；重启后复核状态可恢复，未完成不得显示成功。

### 6.4 灰度开关与共享门禁

拟新增 `MMN_BRAND_CONCLUSIONS_MODE=legacy|shadow|enabled`，默认 `legacy`；另有服务端组织/项目 allowlist，默认空。非法模式 fail-closed 回到 legacy，记录内部配置错误。

- legacy：公共 JSON、已有缓存和旧门禁保持原样，不产生 v4 写入或新增调用。
- shadow：仅显式授权的任务产生隔离 v4 产物；公共回答不变，不因浏览器 GET 自动启动影子分析。
- enabled：只有认证范围命中 allowlist 才投影 v4；不命中继续旧规则。

通用 Eval 若把任何未完成复核都视为整份输出失败，本单只新增 v4 品牌模块适配：允许合格的来源事实单独展示，继续阻断未经验证的策略。必须证明 v3 与其他模块的行为完全不变，不得修改全局硬门禁为宽松默认。

## 8. 测试及业务质量验收

### 8.1 必测矩阵

- 同事实、不同意图侧重：保留事实，不强推单标签。
- 同事实、不同动作：事实与通过的判断保留，动作注明条件与取舍。
- 相反事实/相反趋势：阻断冲突声明，所有依赖动作同步阻断。
- 三路标签一致、正文却无依据：仍拒绝无依据正文，验证旧选文漏洞被封住。
- 不同来源支持同一事件：有效引用分别保留；转载独立来源数不重复。
- 无证据、失效来源、过期时间窗、错误品牌/车型、只有标题：不升级成确定判断。
- 逐竞品只一方有证据、口径不一致：不输出比较优劣或替代因果。
- 通道超时、缺行、JSON失败、401/403、限流、额度耗尽：正确分类、预算有限、状态真实。
- 成功行与失败行混合：成功产物不丢失，修复不得覆盖成功行或借别路答案。
- 人工采纳/修改/否决：持久化、刷新恢复、依赖重检、硬门禁不可豁免。
- 跨租户、伪造 reviewer、证据指纹不匹配、幂等冲突、过期写入：失败关闭。
- 旧 v3 快照、开关关闭、非 allowlist：响应回归一致、零新增调用和业务写入。
- 项目切换、取消、重启、旧请求迟到：新项目不被覆盖。
- 页面与导出如消费本模块：中文状态、无原始模型正文/供应商/凭据泄漏、XSS 输入安全。
- 本地和 Linux 容器均运行新增模块导入、路径、迁移、开关与权限测试。

### 8.2 Gold 与质量门禁

在调规则前冻结至少 60 个声明级案例：至少 30 个来自可追溯真实历史输出；其余可为明确标注的边界/对抗合成案例。覆盖“应发布、仅事实、应保留争议、应阻断”四组，每组至少 10 个。开发集与留出集按证据快照分组，不能把同一快照的相似改写分到两边。

由产品负责人确认标签；开发者不能独自定义全部正确答案。无法取得足够真实原始记录时，可以完成合成机制测试，但质量门禁记为未完成，禁止宣称改善幅度或全量启用。

以下为待评审的发布标准，不是当前成绩：

| 指标 | 口径 | 发布要求 |
| --- | --- | --- |
| 无依据/越界发布 | 在完整留出集及硬门禁集上人工确认的违规发布条数 | 0；出现任一例停止启用 |
| 硬门禁阻断率 | 正确阻断数 / 标注应阻断数 | 100%（仅说明测试集结果） |
| 可恢复有效输出率 | v4 交付至少一条合格实质内容的案例数 / Gold 标注可恢复且被 v3 阻断的案例数 | ≥80%；分母为0则不成立，不能算通过 |
| 引用与范围完整率 | 已发布声明中引用可回读且范围匹配的条数 / 已发布声明数 | 100% |
| 模型成本与延迟 | 每轮调用、重试、token、耗时、估算费用，分别报告真实与合成 | 不越第6.3节硬上限；实际费用必须有记录，不设虚假下降承诺 |

同时报告旧规则误拦截、新规则误放行、无法回答、人工队列数量，不以“有字输出率”代替质量。未校准前不对客户显示正确率概率。

## 9. 双环境发布前置条件

1. W0—W4 定向测试、完整回归、真实浏览器与独立代码审查完成；Critical/Required 为0。
2. 发布候选来自明确 Git commit/tag，只有本单变更及经核准的既有运行基线；保留功能差异清单。禁止 `git add .`、从脏工作树整包发布或顺带上线其他工作。
3. 本地工作树、受管运行包、GitHub、服务器目前可能不同。必须先核对四方代码清单；本地已有 UI 和知识工作区等功能不得回退。若无法构建保留各环境已上线功能的可审计候选，暂停发布，提交基线合并方案，不能以覆盖解决。
4. 记录 releaseId、Git SHA、规则/schema版本、全包及关键文件 SHA-256、依赖锁定、开关、allowlist、迁移版本、目标环境与回滚点。两个环境的核心规则、前端合同与测试夹具哈希一致；不可避免的基线差异逐项列明，不假称整包一致。
5. 本地/服务器分别读取真实监听者或容器身份、数据根、挂载、磁盘容量、活动任务、定时任务和关键配置。活动任务不明或 persistentCheck 不通过时禁止切换，不能强杀任务。
6. 维护窗口先阻止新写任务并排空已有任务；记录并在验收后恢复原调度状态。备份源码/镜像、必要配置、数据库、导入资产与当前开关；凭据不进入公开回执。
7. SQLite 使用一致性备份或全写者停写后的安全副本；不能仅对正在写入的数据目录执行普通 cp 后宣称备份一致。必须 quick_check、恢复演练和表级逻辑比对。存在其他持久数据库时也必须纳入清单及备份。
8. 代码安装阶段 legacy 模式，不因打包或启动自动重算旧快照；表结构仅增量创建、旧程序可忽略，不删除/改名旧列。

## 11. 服务器部署、启用和验收

### 11.1 目标与当前未知

仅 MMN 自有服务器在范围内；文档历史目录为 `/opt/mmn-perception-engine`，部署形态为 Docker Compose。服务器当前版本、实际路径、入口、容器名、域名/TLS状态须在正式发布前只读核对。本轮未 SSH 核验，不把旧记录当当前状态。

备案/公网 HTTPS 的历史阻塞按用户既有决定处理；本单不申请证书、不修改 DNS、安全组或其他产品反向代理。若公网受阻，可在受控 SSH 隧道下完成源站鉴权业务验收，回执必须写“服务器源站已验收，公网入口未验收”；不能宣称公网交付全部完成，也不使用不安全公网连接传递管理员凭据。

### 11.2 仅代码发布能力（本单必须补齐）

现有 `scripts/deploy.sh` 会同步销量、产品评价和 RAG 等资产；`scripts/rollback.sh` 要求服务器存在 `.git`。不能把二者直接当作本单无副作用的发布/回滚保证。

新增显式 `MMN_DEPLOY_CODE_ONLY=true` 模式：默认行为不变，保留其他合法版本发布所需的资产同步；本单启用该模式时不复制种子或业务 data/imports、不做双向数据同步、不迁移本地主库。所有依赖/镜像预构建和配置检查须在停止旧服务前完成，构建失败旧服务保持可用。

服务器使用经发布授权提交并推送的确定 commit 归档，或对应不可变镜像；记录归档哈希和镜像 digest。无 `.git` 环境设置 `MMN_SKIP_GIT_PULL=true` 并核验归档，不使用 `git pull main` 漂移到未经测试的新提交。禁止在服务器手工编辑业务代码，禁止 `down -v`、删卷、整目录覆盖数据或 `sync-local-primary.sh`。

尽量仅重建受影响应用服务；反向代理必要重载需验证上游连接。只有配置/代码依赖确实涉及其他服务且维护窗口已覆盖时才重启它们，不无条件停掉全套 Compose。新配置只增量注入本单键，既有密钥、登录要求、卷映射保持原样。

### 11.3 服务器验收

1. 核对容器实际镜像 digest、运行代码/资源哈希、规则/schema、持久化卷和开关，不能只看 GitHub 已推送。
2. legacy 模式启动，readiness、真实鉴权只读接口、历史快照全部通过。
3. Linux 下执行本模块定向测试与兼容性检查；测试 DB 指向独立临时根，不在生产库跑会建种子的测试。
4. 显式 allowlist 项目按本地相同业务步骤验收；管理员可复核，试用/无权限用户不可写裁决，跨租户请求不可读写。
5. 真实冻结包至多一组、模型调用遵循预算；超时与冲突等负向案例在隔离 fixture 验证，不伪造线上自然失败。
6. 刷新或重新登录后读取服务器持久结果；不能依赖本机 localStorage 冒充服务器保存。
7. 1440/390px 真实鉴权页面截图、网络与控制台检查；全部受影响入口及公共投影/导出无泄漏。
8. 切换后至少15分钟受控观察：readiness、5xx、未捕获异常、失败任务、引用违规、调用上限、数据差异；记录起止时间与实际样本，不把低流量观察声称为长期稳定性。
9. 输出 `server-acceptance.json`，与本地回执核对相同规则/schema及核心代码哈希，分别列明数据集、基线和入口差异。

## 12. 回滚、保护与停止线

任一情况触发停止启用并回滚：无依据/越界结论发布、串租户、未经批准的数据漂移、无法读取旧快照、主页面失败、持续 readiness 失败、超出调用预算，或 Critical/Required 审查未解决。

回滚分两级：

1. **规则回退**：将模式改回 legacy，撤销本单 allowlist；验证公共输出回到旧投影。已经开始的 v4 任务取消/隔离，迟到结果不得继续对外发布。保留新版本与审计记录，不删库“清场”。
2. **代码回退**：本地用本次安装器实际生成并演练可用的 `agent rollback --backup`；服务器恢复已核验旧镜像/代码归档及本单前配置键，保留持久化卷。无 `.git` 环境不能依赖 `scripts/rollback.sh`。

普通代码回滚不得整库恢复旧备份，避免抹掉发布后的合法业务写入。仅在确认数据损坏且取得明确恢复授权时启动数据恢复，先保存损坏现场与新增合法记录，再给出逐表恢复方案。测试记录默认留在独立测试范围；确需清理，只按预先登记主键和完整内容哈希核验，禁止按日期/品牌批量删除。

本地与服务器都必须在隔离环境演练“旧版→新版 legacy→enabled→legacy→旧代码”，证明旧读者可忽略新增表，历史数据仍可读、模式切换不额外触发模型。
