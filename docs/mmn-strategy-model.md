# MMN Strategy Model

## 一句话定义

MMN Strategy Model 是MMN汽车营销引擎的核心策略层。它把车型、竞品、用户情绪、产品属性、身份认同、认知空位和传播动作组织成一套可复用、可学习、可质检的汽车营销方法论。

底层大模型只负责执行、推理、摘要、表达和质检。MMN真正的护城河，是策略流程、知识库结构、输出规范、数据资产和模型调度逻辑。

## 核心模块

| 模块 | 作用 |
| --- | --- |
| NSR | 判断口碑健康、正负向结构、购买阻力风险 |
| Emotion | 拆解兴奋、认可、信任、期待、怀疑、焦虑、失望等情绪 |
| Attribute | 归纳底盘、智能化、空间、价格、品牌信任、安全、能耗等产品属性 |
| Identity | 识别家庭用户、科技用户、性能用户、价格敏感用户、车主、KOC、KOL等身份 |
| Gap | 判断本品与竞品之间的认知空位和传播缺口 |
| Action | 输出内容、平台、达人、预算、销售承接和复盘动作 |
| RAG知识库 | 召回MMN母库、客户私有库、项目学习库 |
| 周报生成 | 将周期数据转成品牌/车型策略判断 |
| 高管蒸馏 | 将公开表达沉淀为可调用的话术资产 |
| 车型传播分析 | 管理车型资产、内容资产、达人资产、垂媒正反向排名 |

## 标准策略流程

每次汽车营销分析必须按照下面顺序输出：

1. 本品：这台车现在真实问题是什么
2. 竞品：谁在抢同一批用户，抢的是什么心智
3. 用户情绪：用户是在兴奋、认可、怀疑、焦虑还是失望
4. 产品属性：问题落在哪些产品维度
5. 身份认同：是谁在说、谁在信、谁在犹豫
6. 认知空位：本品还有哪个位置没有被用户记住
7. 传播动作：下一步应该做什么内容、找谁说、在哪个平台说、怎么复盘

## 多模型调度原则

MMN不让用户直接选择模型供应商，而是按任务类型自动选择底层AI发动机：

| 任务类型 | MMN调度方式 |
| --- | --- |
| 复杂策略分析 | 优先深度推理引擎，备用中文执行引擎 |
| 中文营销表达 | 优先中文表达稳定的执行引擎 |
| 数据归纳和表格摘要 | 优先稳定摘要引擎 |
| 观点压力测试 | 优先策略推理质检引擎 |
| 高管IP话术 | 先生成，再质检，再输出 |
| 模型失败 | 使用备用模型；仍失败则使用MMN本地规则兜底 |

## 用户侧表达规范

前端统一使用：

- MMN策略模型正在分析
- MMN多模型引擎
- MMN用户感知引擎
- MMN高管蒸馏模型
- MMN周报生成模型
- MMN策略质检
- MMN本地规则兜底

不把Qwen、DeepSeek、OpenAI等底层供应商名称作为用户侧核心卖点展示。

## 后台配置原则

后台可以保留底层模型配置，包括API Key、Base URL、模型名、超时、重试和兜底顺序。配置文件和环境变量不得提交API Key。

未来继续接入客户私有模型、专属云模型、无模型规则引擎或新的模型供应商时，只需要接入调度层，不应该改变MMN品牌和方法论。
