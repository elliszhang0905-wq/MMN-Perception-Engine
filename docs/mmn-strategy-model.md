# MMN Strategy Model

## 一句话定义

MMN Strategy Model 是MMN汽车营销引擎的核心策略层。它把车型、竞品、用户情绪、产品属性、身份认同、认知空位和传播动作组织成一套可复用、可学习、可质检的汽车营销方法论。

在产品层，MMN 统一升级为 **Auto Consulting OS**：以 `develop-auto-marketing-strategy` 为汽车行业核心方法论，使用 `management-consulting` 的问题树、假设树和取舍方法，以及 `market-research` 的研究设计、多源验证和证据透明规则作为补充。补充层不得覆盖汽车购车决策判断。

底层大模型只负责执行、推理、摘要、表达和质检。MMN真正的护城河，是策略流程、知识库结构、输出规范、数据资产和模型调度逻辑。

| 模块 | 作用 |
| --- | --- |

| Positioning | 判断车型应该占据的用户心智位置、竞品对位和传播主张 |
| Gap | 判断本品与竞品之间的认知空位和传播缺口 |

| RAG知识库 | 召回MMN母库、客户私有库、项目学习库 |
| 市场周报 | 将周期数据转成品牌/车型策略判断 |
| 竞品传播分析 | 管理垂媒正反向排名、竞品声量关系和传播机会 |

| 营销智能体矩阵预留 | 为车型策略、竞品传播、达人蒸馏、周报、报告等独立智能体预留边界 |

## 标准策略流程

每次汽车营销分析必须按照下面顺序输出：

1. 本品：这台车现在真实问题是什么
2. 竞品：谁在抢同一批用户，抢的是什么心智
3. 用户情绪：用户是在兴奋、认可、怀疑、焦虑还是失望
4. 产品属性：问题落在哪些产品维度
5. 身份认同：是谁在说、谁在信、谁在犹豫
6. 定位判断：这台车应该占住哪个用户心智位置
7. 认知空位：本品还有哪个位置没有被用户记住
8. 传播动作：下一步应该做什么内容、找谁说、在哪个平台说、怎么复盘

上述流程必须遵守 [MMN Auto Consulting OS 方法论](./mmn-auto-consulting-os.md)。所有数据与结论必须标记为事实、推断、假设或未知；机会地图与策略必须通过独立多源交叉验证和反向压力测试，并输出选项取舍、执行动作、验证指标、停止条件与不做事项。

平台指标、通用咨询框架、模型一致性和机会评分只能作为分析输入，不能代替同预算同场景下的真实汽车候选、购买理由、购买阻力、竞品替代和转化判断。

## 多模型调度原则

MMN不让用户直接选择模型供应商，而是按任务类型自动选择底层AI发动机：

| 任务类型 | MMN调度方式 |
| --- | --- |
| 日常标签识别、内容摘要、达人风格拆解 | 优先 flash/plus 快速模型，避免同步调用旗舰双模型 |
| 复杂策略分析 | 一个旗舰模型先输出主结论，备用模型只在失败或超时时接管 |
| 中文营销表达 | 优先中文表达稳定的快速执行引擎 |
| 观点压力测试 | 另一个旗舰模型作为 critic 后台异步复核逻辑漏洞、证据不足、竞品误判和策略风险 |
| 高管IP表达 | 先生成初版，再按需进行后台质检和人工复核 |
| 模型失败 | 使用缓存、备用模型；仍失败则使用MMN本地规则兜底 |

## 用户侧表达规范

前端统一使用：

- MMN策略模型正在分析
- MMN多模型引擎
- MMN用户感知引擎
- MMN高管蒸馏模型
- MMN周报生成模型
- MMN策略质检
- MMN本地规则兜底

不把Qwen、DeepSeek、Kimi、OpenAI等底层供应商名称作为用户侧核心卖点展示。

## 后台配置原则

后台可以保留底层模型配置，包括API Key、Base URL、模型名、超时、重试和兜底顺序。配置文件和环境变量不得提交API Key。

车型参数与配置类任务继续坚持“来源先于模型”：先读取结构化数据、RAG 或官方来源，再由三个旗舰模型独立复核。只有三者全部完成、均确认来源支持且共同引用同一证据时，系统才标记为“三模型一致”；任何缺失、冲突、无引用或低置信度都进入人工复核。

未来继续接入客户私有模型、专属云模型、无模型规则引擎或新的模型供应商时，只需要接入调度层，不应该改变MMN品牌和方法论。

## 产品边界约束

MMN 当前只服务车企品牌、市场部门、车企代理公司和汽车垂直 MCN。新功能应优先落在车型策略、竞品传播分析、达人蒸馏、内容 brief、脚本生产、品牌/高管 IP 蒸馏、市场周报和策略报告输出。

偏经销商、销售顾问、门店接待、即时销售攻防的场景属于 Credo 产品线，不进入 MMN 的导航、页面命名、权限路径和默认输出。
