# MMN 在线安全发布改造计划

## 目标

消除“先停止线上容器、再长时间构建镜像”导致的持续 502。构建失败、磁盘不足或并发发布时，现有线上版本必须继续服务；切换失败时自动恢复上一运行镜像。

## 实施项

1. 发布任务使用互斥锁，禁止两次发布重叠执行。
2. 构建前检查磁盘空间；空间不足时仅清理无用构建缓存，仍不足则保持旧版在线并终止发布。
3. 在线备份生产数据，并保存上一运行镜像为固定回滚标签。
4. 使用独立候选标签构建和执行 Python 编译烟雾检查，构建阶段不停止任何线上容器。
5. 候选镜像通过后才执行 Compose 原地切换，禁止 `docker compose down`。
6. 主应用或反向代理健康检查失败时，自动将上一镜像恢复为正式标签并重新启动。
7. 发布成功后清理候选标签和构建缓存，避免再次挤满系统盘。

## 验收

- 自动化测试锁定“构建早于切换”且发布脚本不存在整套停机命令。
- 模拟或实际构建期间，公网健康接口持续可访问。
- 发布后全部容器正常，公网首页与健康接口通过。
- SQLite `PRAGMA quick_check` 返回 `ok`。
- 生产数据不由本地数据库覆盖。

## 边界

该改造消除镜像构建期间的分钟级停机，并为切换失败提供自动回滚。单机 Compose 在容器替换瞬间仍可能出现秒级连接重试；若要求严格意义上的零丢包，需要后续升级为双实例蓝绿发布。
