# MMN Perception Engine 智能体研发交接手册

## 1. 交接目的

本文档用于将 MMN Perception Engine 的后续研发工作交接给 Qwen Agent 或其他具备代码执行能力的研发智能体。

接手智能体的角色是“研发执行者”。MMN 的产品定义、策略模型、知识库结构、输出规范和发布节奏由项目所有者决定。接手智能体不得把自身模型能力等同于 MMN 产品能力。

## 2. 项目定位

MMN Perception Engine 是一个多模型驱动的汽车营销策略系统，不是简单的大模型聊天网页。

MMN 的核心资产包括：

- 汽车营销策略模型
- 车型、竞品、用户情绪、产品属性、身份认同、认知空位和传播动作工作流
- MMN 母知识库、客户私有知识库、项目学习库
- 内容资产、达人资产、垂媒正反向排名、车型资产
- 创始人蒸馏、博主/达人蒸馏、内容能力蒸馏
- 策略报告、达人 brief、短视频脚本、账号孵化方案、竞品传播口径输出规范
- 可编辑商业咨询型 PPTX、页面结构 JSON、预览图和自动校验报告输出规范
- 市场周报、客户策略汇报、品牌/高管 IP 表达资产
- 模型调度、RAG 检索、人工复核和研发档案机制

底层模型供应商可以替换，但不得改变 MMN 的品牌和方法论。

后续研发默认围绕车型策略、竞品传播分析、达人蒸馏、内容 brief、脚本生产、品牌/高管 IP 蒸馏、市场周报和策略报告输出展开。偏经销商、销售顾问、门店接待和即时销售攻防的功能属于 Credo，不进入 MMN 默认导航和交付路径。

## 2.1 MMN 与 Credo 产品边界

MMN 与 Credo 是两条独立产品线，不应混成一个系统。

MMN 面向车企品牌、市场部门、车企代理公司和汽车垂直 MCN，核心场景是营销策略、达人蒸馏、内容生产、品牌传播与报告输出。MMN 的页面信息架构、权限模型、交付口径和商业化方式应围绕品牌营销、内容资产与策略交付展开。

Credo 面向经销商、销售顾问和门店管理者，核心场景是本品卖点、竞品对比、销售攻防表达与到店接待辅助。Credo 的页面信息架构、权限模型、交付话术和商业化方式应围绕门店销售和销售顾问即时使用展开。

两者可以共享底层车型知识库、竞品资料和部分数据结构，但前端产品、用户权限、功能路径、交付口径、页面信息架构和商业化模型必须独立设计。禁止把 Credo 的门店销售功能直接塞进 MMN，也禁止把 MMN 的营销策略、达人蒸馏、内容生产和品牌传播功能直接塞进 Credo。

1. 本品
2. 竞品
3. 用户情绪
4. 产品属性
5. 身份认同
6. 定位判断
7. 认知空位
8. 传播动作

## 6. 模型调度规则

用户侧不直接选择 Qwen 或 DeepSeek。前端统一表达为：

- MMN 策略模型正在分析
- MMN 多模型引擎
- MMN 用户感知引擎
- MMN 高管蒸馏模型
- MMN 周报生成模型
- MMN 策略质检
- MMN 本地规则兜底

内部调度原则：

| 任务类型 | 调度原则 |
| --- | --- |
| 日常标签识别、内容摘要、达人风格拆解 | 优先 flash/plus 快速模型，不默认同步调用两个旗舰模型 |
| 策略推理、竞品拆解、反方观点、逻辑压力测试 | 一个旗舰模型先输出主结论，前台先返回初版；另一个旗舰模型只作为后台 critic 复核 |
| 中文交付、短视频脚本、PPT 文案、客户报告、长文档归纳 | 优先中文表达快速模型，深度质检按需后台触发 |
| 参数、销量、价格、配置、上市时间等事实类问题 | 优先结构化数据库、RAG 和官方来源，模型只负责解释 |
| 双模型结论冲突 | 标记“需人工复核”，保留主结论、critic意见、来源、置信度和人工最终选择 |
| 模型不可用或超时 | 使用缓存、备用模型；仍失败则使用 MMN 本地规则兜底 |

任何新增模型能力都必须避免把单一模型原始答案直接暴露为最终策略结论。

必须遵守以下隔离原则：

- 国内版与出海版数据隔离
- 集团、品牌、车型、项目分层
- MMN 母知识库、客户私有知识库、项目学习库分层

- 车型内容库、达人库、内容能力蒸馏库不得混写
- 服务器演示数据与本地主数据不得无控制双向覆盖

不得删除或覆盖：

- `data/`
- `imports/`
- `logs/`
- `docs/研发档案/`
- 用户手动导入的 Excel、CSV、JSON、截图和文本材料

## 8. 合规边界

采集和导入能力只能处理：

- 公开可访问页面
- 用户手动导入数据
- 合法授权导出文件
- 客户提供的内部资料
- 可见页面内容

禁止：

- 绕过验证码
- 绕过登录限制
- 绕过付费墙
- 破解签名或加密
- 伪造登录态
- 注入 Cookie 或 Token
- 批量采集评论区个人信息
- 删除水印
- 把外部观点包装成 MMN 原创结论
- 高度相似仿写外部账号原文

内容蒸馏必须表达为“方法论迁移”和“公开内容样本归纳”，不得冒充原账号。

## 18. BF工厂 P0 交接说明

BF工厂服务品牌客户商业化内容 Brief 闭环，不是普通文档总结器。前台入口为“核心工作流 → MMN策略输出 → BF工厂”，后台入口为“资产沉淀 → BF资产库”。

### 稳定结构与开放范式

- `strategy`、`product`、`content`、`execution`、`risk`、`materials` 六层是稳定知识本体。
- 探店、云评/口播、高质感摄影是种子范式，不得改回封闭三选一模板。
- 未知和混合需求进入 `CUSTOM`，按内容意图动态组合章节。
- 优质 `CUSTOM` 终稿回流后，可沉淀脱敏章节范式；后续相似需求应通过 `find_matching_template_profile` 真正召回使用。

### 关键接口

- `GET/POST /api/bf/projects`
- `GET/POST /api/bf/documents`
- `GET /api/bf/schema`
- `GET /api/bf/briefs` 与 `GET /api/bf/briefs/{id}`
- `POST /api/bf/generations`
- `POST /api/bf/briefs/{id}/versions`
- `POST /api/bf/briefs/{id}/finalizations`
- `POST /api/bf/briefs/{id}/exports`
- `GET /api/bf/template-profiles`
- `GET /api/bf/knowledge-chunks`

### 模型、降级与安全

- 标准链路：DeepSeek内部策略判断 → Qwen中文初稿 → DeepSeek逻辑与风险复核。
- 模型不可用时必须返回 `EDITABLE_DEGRADED`，保留可编辑本地结构化结果。
- 外部模型调用默认脱敏，客户、车型、竞品、预算、联系人、链接和提取码不得进入审计明文。
- 原始文件按组织、客户和项目目录隔离；反例只用于风险，禁用样本不得进入生成上下文。
- 服务器首次构建会安装 LibreOffice、Tesseract中文OCR和Noto CJK字体，构建时间会明显长于纯Python版本；Dockerfile已固定阿里云Debian镜像源，并设置30秒超时与3次重试，避免官方源长时间挂起。
