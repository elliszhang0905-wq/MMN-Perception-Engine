# MMN Eval v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local, repeatable MMN evaluation system that applies deterministic hard gates, scores strategy quality, routes disputed cases to the MMN human owner, and compares baseline and candidate outputs without changing existing product flows.

**Architecture:** Add a standalone `mmn_eval` Python package with strict JSONL contracts, a versioned rubric, deterministic scoring, paired comparison, and JSON/Markdown reports. Keep v0.1 offline and standard-library-only so it can run in local development and CI without model keys; model-judge and full Langfuse integration remain later slices behind the same contracts.

**Tech Stack:** Python 3 standard library, `unittest`, JSON/JSONL, Markdown documentation.

## Global Constraints

- MMN and Credo remain separate in data, wording, configuration, and evaluation cases.
- Facts, inferences, hypotheses, and unknowns must remain distinguishable.
- Platform heat, engagement, sentiment, model agreement, confidence, and opportunity scores cannot independently prove purchase opportunity or conversion.
- Vehicle-configuration facts require Qwen, DeepSeek, and Kimi completion plus common evidence before they can pass.
- Missing data must never be converted to zero.
- Any hard-gate violation overrides the numeric score.
- v0.1 must not modify MMN navigation, UI, existing routes, existing database files, or current model-provider functions.
- User-visible naming remains `MMN模型输出策略` or `MMN多模态策略输出`; provider names are internal QA metadata only.
- No API keys, raw private customer material, or personal data may enter fixtures or reports.

---

## File Structure

- `mmn_eval/__init__.py`: public package exports and rubric version.
- `mmn_eval/contracts.py`: validation and normalization for cases, outputs, evidence, human labels, and run metadata.
- `mmn_eval/rubric.py`: versioned hard gates, weighted dimensions, thresholds, and task-specific requirements.
- `mmn_eval/scorer.py`: deterministic gate evaluation, weighted scoring, verdict assignment, and human-review reasons.
- `mmn_eval/runner.py`: JSONL loading, per-case evaluation, aggregate metrics, paired baseline/candidate comparison, and report rendering.
- `scripts/run_mmn_eval.py`: command-line entry point.
- `data/eval/mmn_eval_seed_v0.1.jsonl`: synthetic, non-sensitive seed cases covering success and failure modes.
- `data/eval/mmn_eval_seed_outputs_v0.1.jsonl`: synthetic candidate outputs used to prove pass, review, and hard-fail behavior.
- `docs/mmn-eval.md`: operator guide, annotation guide, report interpretation, and human review workflow.
- `tests/test_mmn_eval_contracts.py`: schema and normalization tests.
- `tests/test_mmn_eval_scorer.py`: hard-gate and weighted-score tests.
- `tests/test_mmn_eval_runner.py`: JSONL runner and regression comparison tests.
- `docs/研发档案/2026-07-17_beta-1.02_MMN-Eval-v0.1.md`: required development record.

## Human Review Checkpoints

The MMN owner is called only when one of these conditions occurs:

1. Two plausible rubric interpretations change pass/fail behavior.
2. A real case remains disputed after deterministic checks and anonymized dual review.
3. The initial seed run is ready to freeze pass/review/fail thresholds for v0.1.

## Deferred Slices

- Full provider-call Trace integration across `call_provider`, direct Qwen/DeepSeek calls, BF model calls, and creator distillation.
- Langfuse dataset synchronization and live model-judge execution.
- Extraction of 120-150 real, redacted cases from historical runs and human reviews.
- CI/release-gate enforcement after the MMN owner freezes v0.1 thresholds.
