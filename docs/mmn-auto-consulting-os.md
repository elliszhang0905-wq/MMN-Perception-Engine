# MMN Auto Consulting OS 方法论

## 1. 定位与方法论优先级

MMN 是面向汽车品牌市场、代理公司与汽车垂直内容组织的 Auto Consulting OS。它不是通用咨询框架生成器，也不是平台指标看板的包装层。

方法论优先级固定为：

1. `develop-auto-marketing-strategy`：MMN 汽车行业核心方法论，负责把车型、竞品、用户、场景、心智、内容与购车决策连接起来。
2. `management-consulting`：只补充问题定义、问题树、假设树、选项比较、取舍与反向压力测试。
3. `market-research`：只补充研究设计、来源治理、样本边界、多源交叉验证与证据透明。

后两层不得覆盖汽车行业判断。任何通用框架只能帮助组织问题，不能替代真实的车型购买理由、购买阻力、竞品替代关系、用户场景和线索转化判断。

## 2. 汽车购车决策主链

任何机会或策略必须至少解释以下链路中的相关环节：

`需求触发 → 候选车型集合 → 场景与人群适配 → 产品利益感知 → 证据可信度 → 购买风险与阻力 → 竞品替代判断 → 到店/试驾/询价/下订 → 使用反馈与口碑回流`

以下内容不能单独构成汽车策略结论：

- 单个平台的曝光、点赞、评论、收藏或热搜排名。
- 没有对应人群、车型版本、价格带和使用场景的参数比较。
- SWOT、PESTLE、五力、漏斗、4P 等通用框架名称或模板。
- 没有连接到候选集合、购买理由、购买阻力或转化动作的“声量机会”。
- 由模型置信度、机会分或平台热度直接推导的策略优先级。

## 3. 问题树与假设树

### 3.1 决策问题

每次分析先写成一个可决策的问题，至少包含：

- 决策对象：品牌、车型、版本或项目。
- 目标人群与购车阶段。
- 需要做出的选择。
- 时间、预算、渠道与组织约束。
- 成功标准和不可接受结果。

禁止用“提升声量”“强化心智”“做大曝光”等不可证伪表述代替决策问题。

### 3.2 汽车行业问题树

问题树默认从购车决策拆解，而不是从平台指标拆解：

1. 候选集合：本品是否进入目标人群的初始候选，为什么进入或被排除。
2. 价值判断：哪些产品利益在真实场景中可感知，哪些只是参数存在。
3. 风险判断：价格、质量、安全、能耗、补能、保值、品牌信任和服务等阻力如何影响决策。
4. 竞品替代：用户在同一预算、场景和时间窗口内实际比较谁，取舍是什么。
5. 证据可信：官方说明、第三方实测、车主体验和真实行为是否相互支持。
6. 转化承接：内容与渠道动作如何推动搜索、留资、到店、试驾、询价或下订。

问题树应尽量互斥且穷尽，但不得为了 MECE 强行切断真实因果关系。每个末端问题必须能由数据、访谈、实验或明确的未知项回答。

### 3.3 假设登记

每条非平凡判断必须维护：

| 字段 | 要求 |
| --- | --- |
| 假设 | 一句话、可证伪，不得写成愿望 |
| 决策影响 | 假设成立或不成立分别改变什么选择 |
| 支持证据 | 证据 ID、来源、时间和适用范围 |
| 反对证据 | 最强反例与冲突来源 |
| 验证方法 | 补数、访谈、A/B、实测或业务观察 |
| 通过阈值 | 预先定义的判断标准 |
| 终止条件 | 何时停止投入、降级或否定策略 |
| 状态 | 待验证、部分支持、被支持、被否定或未知 |

## 4. 证据透明：四类声明

所有数据、图表、机会点、结论和策略都必须显式标记为以下四类之一：

### 事实 Fact

可由当前证据直接核验。必须附来源、证据 ID、发布日期或采集时间、样本范围、车型/版本和适用边界。来源过期、版本不明或样本范围缺失时，不得标为事实。

### 推断 Inference

由一个或多个事实推导出的解释或判断。必须写出推理链、使用的事实、替代解释和置信边界。模型一致不等于事实，只能提高推断的审查强度。

### 假设 Hypothesis

尚未获得充分支持、但值得验证的可证伪命题。必须说明验证动作、指标、阈值、负责人或数据来源，以及被否定后的替代路径。

### 未知 Unknown

当前证据无法回答的关键问题。必须说明未知对决策的影响、需要补充什么证据、在未知消除前哪些动作不能做。禁止隐藏未知或用通顺文案填补空白。

估算值不得伪装成事实：有实际测量依据时标为事实并公开方法；依赖假设时归入推断或假设，并公开计算方法与敏感性。

## 5. 多源交叉验证

### 5.1 独立性

多条转载、同一稿件的不同平台分发、同一数据库的二次引用、两个模型阅读同一份材料，都只算一个来源。交叉验证必须记录来源之间是否独立。

### 5.2 最低证据组合

机会地图进入“可执行”状态前，至少需要两类独立来源，且必须包含与汽车购买判断直接相关的证据：

- 产品与版本事实：官方配置、监管/认证、价格权益、发布资料。
- 真实体验或行为：第三方实测、车主反馈、搜索/咨询/试驾/成交线索、售后或质量反馈。
- 竞争与市场：同预算同场景竞品、终端价格、销量结构、渠道反馈或权威行业数据。
- 传播表现：平台内容、垂媒声量、评论情绪、达人内容与搜索趋势。

传播表现不能单独证明购买机会。至少一条证据必须说明“为什么这会改变候选、比较、信任、风险或转化”。高风险策略、重大预算或对外发布结论原则上需要三类来源交叉支持。

### 5.3 冲突处理

来源冲突时不得平均化或选择更顺眼的结论。必须保留冲突双方，检查车型版本、时间窗口、样本人群、地域、渠道、利益相关方和采集方法，并将结论降级为推断、假设或未知，直到冲突被解释。

## 6. 反向压力测试

每张机会地图和每项主策略在发布前必须回答：

1. 什么证据最能推翻当前结论？
2. 是否把平台热度误当购买意愿，把相关性误当因果？
3. 是否存在样本偏差、幸存者偏差、车主/潜客混淆或地域偏差？
4. 是否混用了不同车型版本、配置、价格权益或时间窗口？
5. 竞品是否真在同一预算、场景和候选集合内？
6. 如果竞争对手采取最强反制，本策略还成立吗？
7. 如果关键假设错误，最坏损失、止损点和替代方案是什么？
8. 哪些证据来自品牌自身，哪些来自独立第三方或真实行为？

压力测试发现关键证据不足、强反例未解释或终止条件缺失时，策略不得进入“可执行”状态。

## 7. 机会地图契约

每个机会点至少输出：

- 决策问题与汽车购车决策环节。
- 声明类型：事实、推断、假设或未知。
- 支持证据、反对证据、来源独立性和适用边界。
- 本品与真实竞品在同预算同场景下的取舍。
- 购买理由、购买阻力和可感知场景。
- 反向压力测试结果和可能推翻结论的条件。
- 明确优先级及其机会成本，而不只是机会分。
- 可执行动作、负责人/协作方、时间窗口和前置依赖。
- 领先指标、结果指标、验证阈值、观察周期和停止条件。
- 不做事项。

缺少上述关键字段的机会点只能进入“待补证/待人工确认”，不得自动成为执行建议。

## 8. 策略交付契约

策略输出固定回答：

1. 决策：现在要选择什么，为什么。
2. 事实：哪些信息已被证据直接确认。
3. 推断：事实如何连接到汽车购车判断，替代解释是什么。
4. 假设：哪些关键命题尚待验证。
5. 未知：哪些缺口可能改变决策。
6. 选项与取舍：至少两个真实可选方案、收益、成本、风险和机会成本。
7. 推荐路径：选择一个主路径并说明放弃其他路径的原因。
8. 执行动作：对象、场景、内容、渠道、负责人、节奏和依赖。
9. 验证指标：领先指标、结果指标、基线、目标、窗口和停止条件。
10. 不做事项：明确哪些动作、渠道、人群或表达本轮不投入，以及原因。

如果信息不足，必须如实输出未知与补证计划。禁止为了“完整交付感”隐藏数据缺口、编造数字或用通用咨询术语填充。

## 9. 质量门禁

以下任一情况成立时，不得宣称机会或策略已验证：

- 未区分事实、推断、假设和未知。
- 只有单一来源，或所谓多源实际不独立。
- 只有平台指标，没有汽车购买决策证据。
- 没有最强反例、反对证据或压力测试。
- 没有明确取舍、执行动作、验证指标或不做事项。
- 竞品、车型版本、价格带、人群或时间窗口不一致。
- 用模型一致、模型置信度、机会分或框架完整度替代证据强度。

## 10. 与既有 MMN 架构的关系

Auto Consulting OS 不新增、删除、迁移或重命名 MMN 一级/二级模块。它是横跨决策驾驶舱、机会地图、认知赛道、内容资产、BF 工厂、周报和策略报告的统一方法论与输出契约。

现有 NSR、Emotion、Attribute、Identity、Positioning、Gap、Action 和 RAG 保持不变，但所有模块输出都必须遵守本文件的证据分类、交叉验证、压力测试和决策交付规则。
